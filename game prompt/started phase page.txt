started phase page:
One-line summary
When games.phase === 'started' clients redirects to the game_started dynamic page. The client renders stats, the master calling sheet (1–75), recent calls, and the player’s 5×5 preview using a bundled mapping BUNDLED_CARDS[board_id] → bingo_card (client never fetches bingo_card from DB). The server runs an in-memory 3-second loading window then sets games.calling_started = TRUE and calls numbers every 2s. Claims require header x-telegram-init-data, are checked server-side, and are protected by an in-memory sliding-window rate limiter (detailed below). The server silently ignores most invalid/no-op requests except when the header is missing or when rate-limit is exceeded (429). All UI is authoritative from DB updates delivered via Supabase Realtime.

4 . Server authority & high-level rules
When a server process sees games.phase === 'started' (i.e., game was moved to started by picking-phase), the Started controller does:
 1. Start an in-memory 3-second timer. While this timer runs:
   - Keep games.calling_started = FALSE (DB) — clients show Loading.
   - Do not increment games.called_index.
   - Reject/ignore Bingo claim requests (see claim handler rules).
 2. After 3s:
   - Update games.calling_started = TRUE (DB) — clients switch Loading → Started.
   - Begin the calling loop: increment games.called_index every 2s (persisted). Continue until 75 or until a winner acceptance window opens.

Claim acceptance gate
- Server must not accept Bingo claims until games.calling_started === TRUE.
Header & signature handling
- Requests must include x-telegram-init-data header.
  - If header missing → immediate reject (return short error).
  - If header present but signature invalid → silent ignore (no DB writes, no broadcasts).
Silent-ignore policy (others)
- For invalid/no-op cases the server silently ignores requests (no DB writes, no Realtime broadcasts) except where specified:
  - invalid signature → silent ignore
  - user not found → silent ignore
  - phase not started / calling_started false → silent ignore
  - player_picks mismatch or player_picks.invalid === true → silent ignore
  - acceptance window not open / etc. → silent ignore
Note: rate-limit violation is an explicit 429 (not silent ignore) per your request below.

5. Sliding-window rate limiting (per-user, in-memory) — exact implementation
Goal: limit abusive claim attempts; use sliding-window per-user tracking.
Data structure
 - Module-scoped Map<number, number[]> where key = telegram_id and value = array of timestamps in milliseconds.
// Node/TS example
const rateLimitMap = new Map<number, number[]>(); // telegram_id -> [ts1, ts2, ...]
const RATE_LIMIT_WINDOW_MS = 60_000; // 60 seconds
const RATE_LIMIT_MAX = 2; // max requests in window

Per-request algorithm (run before DB work / validation)
 1. const now = Date.now();
 2. let timestamps = rateLimitMap.get(telegram_id) || [];
 3. timestamps = timestamps.filter(ts => now - ts < RATE_LIMIT_WINDOW_MS); (drop entries older than 60s)
 4. if (timestamps.length >= RATE_LIMIT_MAX) {
   - Respond with HTTP 429 and JSON:
{ "error": "RATE_LIMIT_EXCEEDED", "message": "Too many Claim. Try again later." }
   - On the frontend: call toast.error("Too many Claim. Try again later.").
   - Do not proceed with further processing.
 5. else {
   - timestamps.push(now);
   - rateLimitMap.set(telegram_id, timestamps);
   - Continue processing the claim request.
 6. Notes:
   - This is in-memory only (per-process).
   - Use ms resolution for precision.
   - The front-end user-visible message for 429 is the toast above; server must return 429 status code.

-- ----------------------------------------------------------------------
-- Helper function: check_bingo
-- Returns TRUE if the card has any winning line (row, column, diagonal,
-- or four corners) using the provided called numbers.
-- The centre cell (row 3, column 3) is always considered marked.
-- Defensively handles missing or malformed JSON cells.
-- ----------------------------------------------------------------------
CREATE OR REPLACE FUNCTION check_bingo(card jsonb, called jsonb)
RETURNS boolean
LANGUAGE plpgsql
STABLE
AS $$
DECLARE
    i INT;
    j INT;
    cell_text TEXT;
    cell INT;
    marked BOOLEAN;
    diag1 BOOLEAN := TRUE;
    diag2 BOOLEAN := TRUE;
    corners_ok BOOLEAN;
    called_set INT[];
BEGIN
    -- Convert called numbers into an array; if none, use empty array
    SELECT COALESCE(array_agg(value::int), '{}'::int[]) INTO called_set
    FROM jsonb_array_elements_text(called) AS t(value);

    -- ------------------------------------------------------------------
    -- Check rows and columns
    -- ------------------------------------------------------------------
    FOR i IN 0..4 LOOP
        -- Row i
        marked := TRUE;
        FOR j IN 0..4 LOOP
            IF i = 2 AND j = 2 THEN
                CONTINUE;  -- centre is free
            END IF;
            cell_text := card->i->>j;
            IF cell_text IS NULL THEN
                marked := FALSE;
                EXIT;
            END IF;
            cell := cell_text::int;
            IF NOT (cell = ANY(called_set)) THEN
                marked := FALSE;
                EXIT;
            END IF;
        END LOOP;
        IF marked THEN
            RETURN TRUE;
        END IF;

        -- Column i
        marked := TRUE;
        FOR j IN 0..4 LOOP
            IF j = 2 AND i = 2 THEN
                CONTINUE;  -- centre is free
            END IF;
            cell_text := card->j->>i;
            IF cell_text IS NULL THEN
                marked := FALSE;
                EXIT;
            END IF;
            cell := cell_text::int;
            IF NOT (cell = ANY(called_set)) THEN
                marked := FALSE;
                EXIT;
            END IF;
        END LOOP;
        IF marked THEN
            RETURN TRUE;
        END IF;
    END LOOP;

    -- ------------------------------------------------------------------
    -- Main diagonal (top‑left to bottom‑right)
    -- ------------------------------------------------------------------
    FOR i IN 0..4 LOOP
        IF i = 2 THEN
            CONTINUE;  -- centre is free
        END IF;
        cell_text := card->i->>i;
        IF cell_text IS NULL THEN
            diag1 := FALSE;
            EXIT;
        END IF;
        cell := cell_text::int;
        IF NOT (cell = ANY(called_set)) THEN
            diag1 := FALSE;
            EXIT;
        END IF;
    END LOOP;
    IF diag1 THEN
        RETURN TRUE;
    END IF;

    -- ------------------------------------------------------------------
    -- Anti‑diagonal (top‑right to bottom‑left)
    -- ------------------------------------------------------------------
    FOR i IN 0..4 LOOP
        IF i = 2 THEN
            CONTINUE;  -- centre is free
        END IF;
        cell_text := card->i->>(4 - i);
        IF cell_text IS NULL THEN
            diag2 := FALSE;
            EXIT;
        END IF;
        cell := cell_text::int;
        IF NOT (cell = ANY(called_set)) THEN
            diag2 := FALSE;
            EXIT;
        END IF;
    END LOOP;
    IF diag2 THEN
        RETURN TRUE;
    END IF;

    -- ------------------------------------------------------------------
    -- Four Corners: (0,0), (0,4), (4,0), (4,4)
    -- ------------------------------------------------------------------
    cell_text := card->0->>0;
    corners_ok := cell_text IS NOT NULL AND (cell_text::int = ANY(called_set));

    cell_text := card->0->>4;
    corners_ok := corners_ok AND cell_text IS NOT NULL AND (cell_text::int = ANY(called_set));

    cell_text := card->4->>0;
    corners_ok := corners_ok AND cell_text IS NOT NULL AND (cell_text::int = ANY(called_set));

    cell_text := card->4->>4;
    corners_ok := corners_ok AND cell_text IS NOT NULL AND (cell_text::int = ANY(called_set));

    IF corners_ok THEN
        RETURN TRUE;
    END IF;

    -- No winning pattern found
    RETURN FALSE;
END;
$$;

-- ----------------------------------------------------------------------
-- Main claim function: claim_bingo (auto-detects current game)
-- Called when a user clicks the BINGO! button during the started phase.
-- It automatically uses the latest game and performs all authoritative
-- checks atomically.
-- ----------------------------------------------------------------------
CREATE OR REPLACE FUNCTION claim_bingo(
    p_board_id     SMALLINT,
    p_telegram_id  BIGINT,
    OUT result     JSONB
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_game          RECORD;
    v_pick          RECORD;
    v_called_numbers JSONB;
    v_is_win        BOOLEAN;
BEGIN
    -- 1. Lock and read the current active game (latest game_id)
    SELECT phase, calling_started, shuffled_nums, called_index
    INTO v_game
    FROM games
    ORDER BY game_id DESC
    LIMIT 1
    FOR UPDATE;

    IF NOT FOUND THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'No active game');
        RETURN;
    END IF;

    -- 2. Verify game is in started phase and calling has started
    IF v_game.phase != 'started' OR v_game.calling_started != TRUE THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'Game not ready for claims');
        RETURN;
    END IF;

    -- 3. Lock and read the player's pick for this game
    SELECT * INTO v_pick
    FROM player_picks
    WHERE game_id = (SELECT game_id FROM games ORDER BY game_id DESC LIMIT 1)  -- same as v_game's game_id
      AND board_id = p_board_id
    FOR UPDATE;

    IF NOT FOUND THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'Pick not found');
        RETURN;
    END IF;

    -- 4. Check ownership and that the board is not already invalid/winner
    IF v_pick.telegram_id != p_telegram_id THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'Not your board');
        RETURN;
    END IF;

    IF v_pick.invalid THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'Board already invalid');
        RETURN;
    END IF;

    IF v_pick.winner THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'Already a winner');
        RETURN;
    END IF;

    -- 5. Build the list of called numbers up to the current called_index
    SELECT COALESCE(jsonb_agg(value ORDER BY idx), '[]'::jsonb)
    INTO v_called_numbers
    FROM jsonb_array_elements(v_game.shuffled_nums) WITH ORDINALITY AS elem(value, idx)
    WHERE idx <= v_game.called_index;

    -- 6. Validate whether the card actually has a bingo
    v_is_win := check_bingo(v_pick.bingo_card, v_called_numbers);

    IF v_is_win THEN
        -- 7a. Winner – update the pick, fetching the user's first_name atomically
        UPDATE player_picks
        SET winner = TRUE,
            winner_name = (SELECT first_name FROM users WHERE telegram_id = p_telegram_id)
        WHERE game_id = (SELECT game_id FROM games ORDER BY game_id DESC LIMIT 1)
          AND board_id = p_board_id;

        result = jsonb_build_object(
            'success', true,
            'action', 'winner',
            'winner', true,
            'message', 'Bingo confirmed'
        );
    ELSE
        -- 7b. Not a winner – mark the board as invalid
        UPDATE player_picks
        SET invalid = TRUE
        WHERE game_id = (SELECT game_id FROM games ORDER BY game_id DESC LIMIT 1)
          AND board_id = p_board_id;

        result = jsonb_build_object(
            'success', true,
            'action', 'invalid',
            'winner', false,
            'message', 'No bingo'
        );
    END IF;

EXCEPTION
    WHEN OTHERS THEN
        result = jsonb_build_object('success', false, 'action', 'error', 'message', SQLERRM);
END;
$$;

// this pg function is used for finalzing winners and No-winner flow.  
CREATE OR REPLACE FUNCTION finalize_game()
RETURNS JSONB
LANGUAGE plpgsql
AS $$
DECLARE
    v_game           games%ROWTYPE;
    v_winner_count   INT;
    v_prize_cents    BIGINT;
    v_base_cents     BIGINT;
    v_rem_cents      INT;
    v_share_cents    BIGINT;
    v_share_num      NUMERIC(12,2);
    v_winner_rec     RECORD;
    v_result         JSONB;
    v_i              INT := 0;
BEGIN
    -- 1. Lock and fetch the current (latest) game row
    SELECT * INTO v_game
    FROM games
    ORDER BY game_id DESC
    LIMIT 1
    FOR UPDATE;

    IF NOT FOUND THEN
        RETURN jsonb_build_object(
            'success', false,
            'error', 'NO_GAME_FOUND'
        );
    END IF;

    -- 2. Only started games can be finalized
    IF v_game.phase != 'started' THEN
        RETURN jsonb_build_object(
            'success', false,
            'error', 'INVALID_PHASE',
            'phase', v_game.phase,
            'game_id', v_game.game_id
        );
    END IF;

    -- 3. Count winners (NO FOR UPDATE – rows will be locked in the loop)
    SELECT COUNT(*) INTO v_winner_count
    FROM player_picks
    WHERE game_id = v_game.game_id AND winner = TRUE;

    -- 4. Process based on winner count
    IF v_winner_count > 0 THEN
        -- Convert prize to cents for exact distribution
        v_prize_cents := (v_game.prize_amount * 100)::BIGINT;
        v_base_cents  := v_prize_cents / v_winner_count;   -- integer division truncates
        v_rem_cents   := v_prize_cents - v_base_cents * v_winner_count;  -- remainder 0..(v_winner_count-1)

        -- Loop through winners in a deterministic order (e.g., by board_id)
        FOR v_winner_rec IN
            SELECT board_id, telegram_id
            FROM player_picks
            WHERE game_id = v_game.game_id AND winner = TRUE
            ORDER BY board_id   -- stable order
            FOR UPDATE          -- lock each winner row
        LOOP
            v_i := v_i + 1;
            -- First v_rem_cents winners get one extra cent
            IF v_i <= v_rem_cents THEN
                v_share_cents := v_base_cents + 1;
            ELSE
                v_share_cents := v_base_cents;
            END IF;

            -- Convert cents to NUMERIC(12,2) for wallet update
            v_share_num := (v_share_cents::NUMERIC / 100)::NUMERIC(12,2);

            -- Credit the winner's withdrawal wallet
            UPDATE users
            SET withdrawal_wallet = withdrawal_wallet + v_share_num
            WHERE telegram_id = v_winner_rec.telegram_id;

            -- Record in winners_history
            INSERT INTO winners_history (game_id, telegram_id, board_id, credited_amount)
            VALUES (v_game.game_id, v_winner_rec.telegram_id, v_winner_rec.board_id, v_share_num);
        END LOOP;

        v_result := jsonb_build_object(
            'success', true,
            'action', 'winners_credited',
            'game_id', v_game.game_id,
            'winner_count', v_winner_count,
            'prize_amount', v_game.prize_amount
        );

    ELSE
        -- No winners → add the entire prize to the game's house_profit
        UPDATE games
        SET house_profit = house_profit + v_game.prize_amount
        WHERE game_id = v_game.game_id;

        v_result := jsonb_build_object(
            'success', true,
            'action', 'house_credited',
            'game_id', v_game.game_id,
            'prize_amount', v_game.prize_amount
        );
    END IF;

    -- 5. Advance game to winner_reveal with a 10‑second countdown
    UPDATE games
    SET phase = 'winner_reveal',
        winner_reveal_ends_at = NOW() + INTERVAL '10 seconds'
    WHERE game_id = v_game.game_id;

    -- 6. Return summary
    RETURN v_result;
END;
$$;

CREATE OR REPLACE FUNCTION create_next_game()
RETURNS BIGINT
LANGUAGE plpgsql
VOLATILE
AS $$
DECLARE
    current_game_id   BIGINT;
    current_phase     TEXT;
    global_status     TEXT;
    new_game_id       BIGINT;
    config_record     RECORD;
BEGIN
    -- ====================================================================
    -- 1. Lock the latest game row (safe under concurrency)
    -- ====================================================================
    BEGIN
        SELECT game_id, phase
        INTO STRICT current_game_id, current_phase
        FROM games
        ORDER BY game_id DESC
        LIMIT 1
        FOR UPDATE;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE EXCEPTION 'No games exist in the database'
            USING HINT = 'The games table must contain at least one row.';
    END;

    -- ====================================================================
    -- 2. Verify the game is in winner_reveal (only then can we finish it)
    -- ====================================================================
    IF current_phase != 'winner_reveal' THEN
        RAISE EXCEPTION 'Current game phase is not winner_reveal (actual: %)', current_phase
        USING HINT = 'Only a game in winner_reveal can be finished to create the next one.';
    END IF;

    -- ====================================================================
    -- 3. Mark the current game as finished
    -- ====================================================================
    UPDATE games
    SET phase = 'finished',
        finished_at = NOW()
    WHERE game_id = current_game_id;

    -- ====================================================================
    -- 4. Lock and read the global game status (prevents admin changes mid‑transaction)
    -- ====================================================================
    BEGIN
        SELECT status
        INTO STRICT global_status
        FROM game_status
        WHERE id = 1
        FOR UPDATE;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE EXCEPTION 'Game status configuration missing (game_status.id = 1)'
            USING HINT = 'Ensure the game_status table contains the required row.';
    END;

    -- ====================================================================
    -- 5. Insert the next game based on global_status
    -- ====================================================================
    IF global_status = 'stopped' THEN
        -- Maintenance game – set all NOT NULL columns explicitly
        INSERT INTO games (
            phase,
            calling_started,
            called_index,
            active_players,
            stake_amount,
            minimum_player,
            picking_ends_at,
            shuffled_nums,
            prize_amount,
            house_profit,
            winner_reveal_ends_at,
            started_at
        ) VALUES (
            'maintenance',
            FALSE,
            0,
            0,
            0,
            0,
            NULL,
            NULL,
            NULL,
            NULL,
            NULL,
            NOW()
        )
        RETURNING game_id INTO new_game_id;

    ELSE
        -- New picking game – global_status must be 'active'
        -- Lock the game_config row to avoid mid‑transaction changes
        BEGIN
            SELECT stake_amount,
                   picking_countdown_end_time,
                   minimum_player
            INTO STRICT config_record
            FROM game_config
            WHERE id = 1
            FOR UPDATE;
        EXCEPTION
            WHEN NO_DATA_FOUND THEN
                RAISE EXCEPTION 'Game configuration missing (game_config.id = 1)'
                USING HINT = 'Ensure the game_config table contains the required row.';
        END;

        -- Use direct interval arithmetic (faster, type‑safe)
        INSERT INTO games (
            phase,
            calling_started,
            called_index,
            active_players,
            picking_ends_at,
            minimum_player,
            stake_amount,
            shuffled_nums,
            prize_amount,
            house_profit,
            winner_reveal_ends_at,
            started_at
        ) VALUES (
            'picking',
            FALSE,
            0,
            0,
            NOW() + config_record.picking_countdown_end_time * INTERVAL '1 second',
            config_record.minimum_player,
            config_record.stake_amount,
            NULL,
            NULL,
            NULL,
            NULL,
            NOW()
        )
        RETURNING game_id INTO new_game_id;
    END IF;

    -- ====================================================================
    -- 6. Return the ID of the newly created game
    -- ====================================================================
    RETURN new_game_id;
END;
$$;

Then the backend set a timout using games.picking_ends_at for a transaction from picking phase to started phase.
Schedule setTimeout(() => closePicking(), durationMs) using the computed picking_ends_at.

11. Realtime & failure modes summary (concise rules to follow)
  - Client UI must be driven only by Supabase Realtime updates of games and player_picks.
  - Missing x-telegram-init-data header → immediate reject (HTTP 400).
  - Invalid signature → silent ignore (no DB writes, no broadcast).
  - Rate-limit exceeded → HTTP 429 with JSON { error: "RATE_LIMIT_EXCEEDED", message: "Too many Claim. Try again later." } and client shows toast.error("Too many Claim. Try again later.").
  - All other invalid/no-op requests → silent ignore (no DB writes, no broadcast).
  - games.calling_started gate must be enforced: server does not accept claims until games.calling_started === TRUE.
  - Acceptance window is in-memory 1s; halt calling during it, accept winners in window, finalize atomically after window.

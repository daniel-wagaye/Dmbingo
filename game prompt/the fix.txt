Great — I’ve gone through the codebase and now understand your current Colyseus-based flow, especially picking and started phases.

Architecture Snapshot

Server runs Express + Colyseus on the same process/port, with a single game_room and global activeRoom reference in server.ts and GameRoom.ts.
Recovery boot flow pre-creates the room, calls recover_game_state(), hydrates Colyseus state, and schedules picking timer if phase is picking in server.ts.
Client realtime source is now Colyseus via useGameRoom.ts and colyseusClient.ts.
Old Supabase realtime hook is intentionally disabled in useRealtimeGame.ts.
Realtime Picking Phase (End-to-End)

UI uses room state + picks map for tile colors and ownership in GamePicking/index.tsx and TileGrid.tsx.
Pick request goes to /api/games/0/pick (path id ignored by backend) in GamePicking/index.tsx.
Backend verifies Telegram init data + per-user rate limit, calls PG pick_board, then mutates room picks (pick/unpick/move) in gameController.ts.
Picking timeout triggers transition_picking(): either extends countdown (setPickingEndsAt) or starts game (startGame) in scheduler.ts.
Client auto-redirects to started when phase changes to started/winner_reveal in GamePicking/index.tsx.
Started Phase (Realtime + Lifecycle)

Started page renders call sheet, current/recent calls, local card marks, and claim button from Colyseus state in GameStarted/index.tsx.
Server enforces 3s loading window (callingStartDelayMs), sets calling_started = true, then increments called_index every 2s while pushing to Colyseus in caller.ts.
Claim endpoint calls PG claim_bingo, updates winner/invalid pick in room, and triggers winner acceptance flow on first winner in gameController.ts.
Acceptance window + finalization uses winnerAcceptanceWindowMs, finalize_game(), sets room to winner_reveal, then after reveal runs create_next_game() and schedules next picking in caller.ts.
Winner reveal modal/countdown is client-driven from winnerRevealEndsAt and winner picks in WinnerRevealModal.tsx.
Cloudflare Tunnel Understanding

game-server.dmzone.top → http://localhost:3000
plus admin/support hosts, then 404 catch-all (from your config.yml).
Client derives websocket URL from VITE_API_URL by converting https -> wss in colyseusClient.ts, so tunnel is compatible for Telegram Mini App realtime as long as VITE_API_URL points to your public game-server hostname.

Admin game-control endpoint (POST /internal/game-control)
Purpose:
Allow a trusted admin service to start the live bingo game. Single JSON command with a static secret header. Exact behavior is idempotent and atomic where DB writes are required.

Contract — HTTP
- Endpoint: POST /internal/game-control
- Headers
  - Content-Type: application/json
  - X-Game-Secret: <SECRET_VALUE>  - required. Immediately reject (401) if it doesn't exist on the header.
- Body (JSON)
  - Only accept exact bodie:
    - {"game":"Start"}
   - Any other JSON structure or extra fields → 400 Bad Request { error: "INVALID_PAYLOAD" }.
- Rate Limit Check (global, in-memory, sliding window):
Before any further processing, enforce a global rate limit using an in-memory sliding window algorithm (single instance). Allow 10 request per 60-second window. If exceeded, return 429 Too Many Requests { "error": "RATE_LIMIT_EXCEEDED" }.
- Pre-check (fast, read-only):
 1. If last_game.phase !== 'maintenance' → 409
{ "error":"ALREADY_STARTED", "message":"Game already started or not in maintenance." }
 2. If game_status.status !== 'active'.  → 409 { error: "GAME_STATUS_IS_NOT_ACTIVE", message: "Game status is not active. can't start game now." }.
Critical create flow (single atomic DB transaction)
Run the following steps inside one DB transaction (use SELECT ... FOR UPDATE locks where shown):
 1. SELECT phase FROM games ORDER BY game_id DESC LIMIT 1 FOR UPDATE;
   - If it exists and phase !== 'maintenance' → ROLLBACK + return 429 ALREADY_STARTED.
 2. SELECT status FROM game_status WHERE id = 1 FOR UPDATE;
   - If status !== 'active' → ROLLBACK + return 409 GAME_STATUS_IS_NOT_ACTIVE.
 3. SELECT * FROM game_config WHERE id = 1; - read stake_amount, picking_countdown_end_time, minimum_player.
 4. Insert a new games row seeded from game_config:
        - phase = 'picking'
        - picking_ends_at = now() + (game_config.picking_countdown_end_time seconds)
        - minimum_player = game_config.minimum_player
        - stake_amount = game_config.stake_amount
 5. COMMIT; — this ensures the old game is fully closed and new game insert are atomic.

- Proceed with the transaction using the validated (or undefined) referral code.

Atomic database transaction (all database writes in one transaction)

The following SQL (PostgreSQL syntax) encapsulates the entire atomic logic.
Assume application variables are passed in:
v_init_telegram_id, v_init_username, v_init_first_name,
v_contact_phone, v_referral_code (the two telegram IDs have already been verified).

sql
DO $$
DECLARE
    v_init_telegram_id   BIGINT := ...;   -- from verified initData
    v_init_username      TEXT   := ...;   -- from initData
    v_init_first_name    TEXT   := ...;   -- from initData
    v_contact_phone      VARCHAR(25) := ...; -- from verified contact (already normalized, e.g., +251912345678)
    v_referral_code      BIGINT := ...;   -- from localStorage, NULL if none

    referrer             RECORD;
    reg_bonus            NUMERIC(12,2);
    referral_amt         NUMERIC(12,2);
    referral_limit       INT;
BEGIN
    -- Fetch current game_config values (single row, id=1)
    SELECT registration_bonus, referral_amount, referral_monthly_limit
    INTO reg_bonus, referral_amt, referral_limit
    FROM game_config
    WHERE id = 1;

    -- Idempotency: check if user already exists by telegram_id
    PERFORM 1 FROM users WHERE telegram_id = v_init_telegram_id;
    IF FOUND THEN
        -- User already registered; no changes needed.
        -- The application will simply return the existing user.
    ELSE
        -- Check if phone_number already exists (different telegram_id)
        PERFORM 1 FROM users WHERE phone_number = v_contact_phone;
        IF FOUND THEN
            -- Update existing user with new telegram_id
            UPDATE users
            SET telegram_id = v_init_telegram_id,
                username = COALESCE(v_init_username, 'Player'),
                first_name = COALESCE(LEFT(v_init_first_name, 12), 'Player')
            WHERE phone_number = v_contact_phone;
        ELSE
            -- Create new user
            INSERT INTO users (
                telegram_id,
                phone_number,
                username,
                first_name,
                non_withdrawal_wallet,
                referral_count,
                last_referred_date,
                created_at
            ) VALUES (
                v_init_telegram_id,
                v_contact_phone,
                COALESCE(v_init_username, 'Player'),
                COALESCE(LEFT(v_init_first_name, 12), 'Player'),
                reg_bonus,
                0,
                NULL,
                NOW()
            );

            -- Handle referral if provided and not self-referral
            IF v_referral_code IS NOT NULL AND v_referral_code != v_init_telegram_id THEN
                -- Lock the referrer row to prevent race conditions
                SELECT * INTO referrer
                FROM users
                WHERE telegram_id = v_referral_code
                FOR UPDATE;

                IF FOUND THEN
                    -- Reset referral count if month changed or first referral
                    IF referrer.last_referred_date IS NULL
                       OR EXTRACT(MONTH FROM referrer.last_referred_date) != EXTRACT(MONTH FROM NOW()) THEN
                        UPDATE users
                        SET referral_count = 0,
                            last_referred_date = NOW()
                        WHERE telegram_id = v_referral_code
                        RETURNING referral_count, last_referred_date
                        INTO referrer.referral_count, referrer.last_referred_date;
                    END IF;

                    -- Now referrer.referral_count reflects the current value after any reset
                    IF referrer.referral_count < referral_limit THEN
                        -- Credit referrer (add to non_withdrawal_wallet)
                        UPDATE users
                        SET non_withdrawal_wallet = non_withdrawal_wallet + referral_amt,
                            referral_count = referral_count + 1,
                            last_referred_date = NOW()
                        WHERE telegram_id = v_referral_code;

                        -- Insert rewarded referral history
                        INSERT INTO referrals_history (
                            referrer_id,
                            referred_user_id,
                            rewarded,
                            rewarded_amount,
                            created_at
                        ) VALUES (
                            v_referral_code,
                            v_init_telegram_id,
                            TRUE,
                            referral_amt,
                            NOW()
                        );
                    ELSE
                        -- Monthly limit exceeded: insert unrewarded history
                        INSERT INTO referrals_history (
                            referrer_id,
                            referred_user_id,
                            rewarded,
                            rewarded_amount,
                            created_at
                        ) VALUES (
                            v_referral_code,
                            v_init_telegram_id,
                            FALSE,
                            0,
                            NOW()
                        );
                    END IF;
                END IF;
                -- If referrer not found, ignore referral (no action)
            END IF;
        END IF;
    END IF;

    COMMIT;
END $$;
All writes are atomic. After the transaction commits, the registration is final.

After transaction commits:
 - Send Telegram sticker and welcome message to the new user: RFERRAL_STICKER_ID
   - Sticker ID: REGISTER_STICKER_ID(.env file)
   - Message: "Welcome to DMbingo! \nYou have been credited with {game_config.registration_bonus} Birr as a welcome bonus."
If referrer was rewarded (i.e., referrals_history inserted with rewarded = true), send them a Telegram message with sticker:
   - Sticker ID: RFERRAL_STICKER_ID(.env file)
   - Message: "congratulations You successfully Invited {referred_first_name}. Your Non withdrawal wallet get credited {referral_amount} ETB."
Return the newly created/updated user row.

const WINDOW_MS = 60_000;
const LIMIT = 5;
const languageRateMap = new Map(); // Map<telegram_id, number[] timestamps>

function isLanguageChangeAllowed(telegram_id) {
  const now = Date.now();
  let arr = languageRateMap.get(telegram_id) || [];
  arr = arr.filter(ts => now - ts < WINDOW_MS); // keep only recent
  if (arr.length >= LIMIT) {
    languageRateMap.set(telegram_id, arr);
    return false;
  }
  arr.push(now);
  languageRateMap.set(telegram_id, arr);
  return true;
}
 - Call this before starting DB transaction. If false → return 429.

async function handlePatchLang(req, res){
  const init = req.header('X-Telegram-Init-Data');
  const telegram_id = verifyInitAndGetTelegramId(init);
  if(!telegram_id) return res.status(401).json({error:'AUTH_FAILED'});

  const newLang = req.body?.language;
  if(!['en','am'].includes(newLang)) return res.status(400).json({error:'INVALID_LANGUAGE'});

  // in-memory rate limit (single-instance)
  if(!isLanguageChangeAllowed(telegram_id)){
    return res.status(429).json({error:'RATE_LIMIT_EXCEEDED'});
  }

  const client = await pool.connect();
  try {
    await client.query('BEGIN');

    // atomic update
    const result = await client.query(
      'UPDATE users SET language=$1 WHERE telegram_id=$2 RETURNING language',
      [newLang, telegram_id]
    );

    if(result.rowCount === 0){
      await client.query('ROLLBACK');
      return res.status(400).json({error:'USER_NOT_FOUND'});
    }

    await client.query('COMMIT');
    return res.status(200).json({success:true, language: result.rows[0].language});

  } catch(err){
    await client.query('ROLLBACK').catch(()=>{});
    console.error(err);
    return res.status(500).json({error:'INTERNAL'});
  } finally {
    client.release();
  }
}

// In‑memory rate limiter for coupon redemption (per user)
const couponRateLimitMap = new Map<number, number[]>(); // telegram_id -> timestamps
const COUPON_RATE_LIMIT_WINDOW = 60_000; // 60 seconds
const COUPON_RATE_LIMIT_MAX = 3; // max 3 attempts per minute

export async function redeemCouponHandler(req: Request, res: Response) {
  try {
    // 1. Verify Telegram initData
    const initData = req.headers['x-telegram-init-data'] as string;
    if (!initData) {
      return res.status(401).json({ error: 'MISSING_INITDATA' });
    }

    const telegramId = await verifyInitData(initData); // throws if invalid
    if (!telegramId) {
      // Silent ignore – return 204 as per spec
      return res.status(204).end();
    }

    // 2. Rate limiting (per user, sliding window)
    const now = Date.now();
    let timestamps = couponRateLimitMap.get(telegramId) || [];
    timestamps = timestamps.filter(ts => now - ts < COUPON_RATE_LIMIT_WINDOW);
    if (timestamps.length >= COUPON_RATE_LIMIT_MAX) {
      return res.status(429).json({ error: 'RATE_LIMIT_EXCEEDED', message: 'Too many attempts. Try again later.' });
    }
    timestamps.push(now);
    couponRateLimitMap.set(telegramId, timestamps);

    // 3. Extract and validate request body
    const { coupon_code } = req.body;
    if (!coupon_code || typeof coupon_code !== 'string') {
      return res.status(400).json({ error: 'MISSING_COUPON_CODE' });
    }

    // 4. Call the PostgreSQL function (no explicit transaction needed)
    const result = await pool.query( // use drizzle
      'SELECT redeem_coupon($1, $2) AS result',
      [coupon_code.trim(), telegramId]
    );
    const dbResult = result.rows[0].result;

    // 5. Map database result to HTTP response
    if (dbResult.success) {
      // Success – construct the user‑friendly message
      const message = `Congratulations! You've received ${dbResult.credited_amount} ETB to your ${dbResult.credit_wallet} wallet from coupon ${dbResult.coupon_code}`;
      return res.status(200).json({
        success: true,
        coupon_prize: dbResult.coupon_prize,
        credited_amount: dbResult.credited_amount,
        credit_wallet: dbResult.credit_wallet,
        coupon_code: dbResult.coupon_code,
        message
      });
    } else {
      // Error – map business code to HTTP status and message
      const errorMapping: Record<string, { status: number; message: string }> = {
        INVALID_COUPON:        { status: 400, message: 'Invalid coupon' },
        COUPON_EXPIRED:        { status: 400, message: 'Coupon has expired' },
        COUPON_FULLY_REDEEMED: { status: 400, message: 'This coupon has been fully redeemed' },
        COUPON_NOT_STARTED:    { status: 400, message: 'Coupon not yet valid' },
        ALREADY_REDEEMED:      { status: 400, message: 'You have already redeemed this coupon' },
        USER_NOT_FOUND:        { status: 400, message: 'User does not exist' },
        INTERNAL_ERROR:        { status: 500, message: 'Something went wrong. Try again.' }
      };

      const mapped = errorMapping[dbResult.code] || { status: 500, message: 'Unknown error' };
      return res.status(mapped.status).json({ error: mapped.message });
    }
  } catch (err) {
    console.error('Unexpected error in redeemCouponHandler:', err);
    return res.status(500).json({ error: 'Internal server error' });
  }
}

PG FUNCTION:

CREATE OR REPLACE FUNCTION redeem_coupon(
    p_coupon_code  TEXT,
    p_telegram_id  BIGINT
) RETURNS JSONB
LANGUAGE plpgsql
AS $$
DECLARE
    v_coupon       coupons%ROWTYPE;
    v_claimed_id   BIGINT;
BEGIN
    -- 1. Lock the coupon row to prevent concurrent redemptions
    SELECT * INTO v_coupon
    FROM coupons
    WHERE coupon_code = p_coupon_code
    FOR UPDATE;

    IF NOT FOUND THEN
        RETURN jsonb_build_object(
            'success', false,
            'code', 'INVALID_COUPON'
        );
    END IF;

    -- 2. Validate coupon state
    IF v_coupon.status = 'expired' THEN
        RETURN jsonb_build_object('success', false, 'code', 'COUPON_EXPIRED');
    END IF;

    IF v_coupon.status = 'finished' THEN
        RETURN jsonb_build_object('success', false, 'code', 'COUPON_FULLY_REDEEMED');
    END IF;

    IF NOW() < v_coupon.starts_at THEN
        RETURN jsonb_build_object(
            'success', false,
            'code', 'COUPON_NOT_STARTED',
            'starts_at', v_coupon.starts_at
        );
    END IF;

    IF NOW() >= v_coupon.expires_at THEN
        RETURN jsonb_build_object('success', false, 'code', 'COUPON_EXPIRED');
    END IF;

    IF v_coupon.current_uses >= v_coupon.max_uses_total THEN
        RETURN jsonb_build_object('success', false, 'code', 'COUPON_FULLY_REDEEMED');
    END IF;

    -- 3. Prevent double‑claim by the same user
    PERFORM 1
    FROM coupon_history
    WHERE coupon_id = v_coupon.coupon_id
      AND user_telegram_id = p_telegram_id
    LIMIT 1;

    IF FOUND THEN
        RETURN jsonb_build_object('success', false, 'code', 'ALREADY_REDEEMED');
    END IF;

    -- 4. Atomically increment coupon usage and update status if needed
    UPDATE coupons
    SET
        current_uses = current_uses + 1,
        status = CASE
            WHEN current_uses + 1 >= max_uses_total THEN 'finished'
            ELSE status
        END
    WHERE coupon_id = v_coupon.coupon_id
      AND current_uses < max_uses_total;

    IF NOT FOUND THEN
        -- Race condition: another request used the last slot just before us
        RETURN jsonb_build_object('success', false, 'code', 'COUPON_FULLY_REDEEMED');
    END IF;

    -- 5. Credit the correct user wallet (defensively handle potential NULL)
    IF v_coupon.credit_wallet = 'withdrawal' THEN
        UPDATE users
        SET withdrawal_wallet = COALESCE(withdrawal_wallet, 0) + v_coupon.coupon_prize
        WHERE telegram_id = p_telegram_id;
    ELSE
        UPDATE users
        SET non_withdrawal_wallet = COALESCE(non_withdrawal_wallet, 0) + v_coupon.coupon_prize
        WHERE telegram_id = p_telegram_id;
    END IF;

    IF NOT FOUND THEN
        -- User does not exist (should not happen after previous checks)
        RETURN jsonb_build_object('success', false, 'code', 'USER_NOT_FOUND');
    END IF;

    -- 6. Record the claim in history
    INSERT INTO coupon_history (
        coupon_id,
        user_telegram_id,
        credited_amount,
        credit_wallet,
        claimed_at
    ) VALUES (
        v_coupon.coupon_id,
        p_telegram_id,
        v_coupon.coupon_prize,
        v_coupon.credit_wallet,
        NOW()
    )
    RETURNING claimed_id INTO v_claimed_id;

    -- 7. Success – return raw data only
    RETURN jsonb_build_object(
        'success', true,
        'coupon_prize', v_coupon.coupon_prize,
        'credited_amount', v_coupon.coupon_prize,
        'credit_wallet', v_coupon.credit_wallet,
        'coupon_code', p_coupon_code
    );

EXCEPTION
    WHEN unique_violation THEN
        RETURN jsonb_build_object('success', false, 'code', 'ALREADY_REDEEMED');
    WHEN OTHERS THEN
        RETURN jsonb_build_object('success', false, 'code', 'INTERNAL_ERROR');
END;
$$;

2. First step (mandatory): Verify the initData HMAC signature using the bot token (as described in the Telegram WebApp docs and your existing verifyInitData middleware).
   - If verification fails → return 401 { "error": "AUTH_FAILED", "message": "Invalid authentication data" }
   - If successful → extract telegram_id from the verified initData.
3. Use this extracted telegram_id for all further operations (rate limiting, user lookup, wallet credit, etc.).
4. Rate limiting (in-memory, per-user):
  - Maintain an in-memory Map<telegram_id, number[]> where each entry is an array of epoch-second (or ms) timestamps of recent attempts.
  - On each request:
    1. timestamps = map.get(telegram_id) || [].
    2. Remove any timestamps older than 60 seconds from timestamps.
    3. If timestamps.length >= 3 → return 429 { error: 'RATE_LIMIT_EXCEEDED', message: 'Too many requests. Try again later.' }.
    4. Else push now to timestamps, map.set(telegram_id, timestamps) and continue processing.
  - This keeps the backend safe from spam and uses almost zero memory even with hundreds of concurrent players.
  - (Note: this is an in-memory per-instance approach — suitable for single-instance or non-strict distributed setups.)
5. Normalize txn_reference = txn_reference.trim().
6. Begin DB transaction.
7. Attempt to find deposit row:
   SELECT * FROM deposits WHERE txn_reference = $1 FOR UPDATE;
8.If no row → ROLLBACK → return 404 { error: 'DEPOSIT_NOT_FOUND', message: 'The Deposit Does Not Exist' }.
9. If row found:
  - If status = 'approved' → ROLLBACK → return 409 { error: 'ALREADY_PROCESSED', message: 'Deposit already processed.' }.
  - If status = 'rejected' → ROLLBACK → return 409 { error: 'REJECTED', message: 'Deposit is Rejected! \\n please reach out to our customers if you think this is a mistake' }.
  - If status = 'pending' → proceed:
    - Credit user non_withdrawal_wallet by deposit.amount. Implementation:
      1. UPDATE users SET non_withdrawal_wallet = non_withdrawal_wallet + $amount WHERE telegram_id = $telegram_id RETURNING telegram_id;
      2. If 0 rows returned → ROLLBACK → return 400 { error: 'USER_NOT_FOUND', message: 'User does not exist' }.
    - Mark deposit processed:

UPDATE deposits
SET status = 'approved',
    telegram_id = $telegram_id,
    processed_at = NOW()
WHERE deposit_id = $deposit_id;

 - Commit transaction.
 - Return `200` `{ success: true, amount: deposit.amount, message: "Your deposit is successfully APPROVED. \\n Your wallet is credited with: \\n {amount} ETB" }`.

Important: Use SELECT ... FOR UPDATE / DB transactions to avoid race conditions and double-crediting.

Request contract (client → server):
 - Headers:
   - x-telegram-init-data: <Telegram initData string> — client MUST include the Telegram WebApp initData string in a request header.
     - The server must verify the initData signature using Telegram's recommended verification (bot token) and extract the telegram_id from the verified initData.
     - If signature verification fails → server returns 401 Unauthorized.
     - If header doesn't exist → server returns 401 Unauthorized.
       Body (JSON):
       { "board_id": 42 }

- Important: the client must not send telegram_id in the request body. Important: the server ignores the path parameter :gameId and derives the acting game id from the current last games row (SELECT max(game_id) FROM games). The server uses the telegram_id extracted from verified initData as the acting user identity.

High-level behavior (single transactional endpoint)
 - Unpick: if clicking own slot → refund and clear ownership (do not change board_id or bingo_card).
 - First-time pick: if no previous pick → verify balance, debit (withdrawal first then non-withdrawal), claim slot and store used amounts.
 - Move-pick: if user had a pick → clear old slot and claim new slot transferring stored used amounts (no extra debit).
 - Race: if target slot is taken by someone else for same game_id → 409 BOARD_TAKEN.
 - User missing rule: After verifying initData and extracting telegram_id, the backend must check whether telegram_id exists in users. If the user does not exist, the backend must abort silently: do no writes, do not emit realtime events, and return 204 No Content. (This is deliberate: silent abort, no errors shown to the client.)
 - All done inside a single DB transaction with strict lock ordering. Backend uses service role for writes.

5. Sliding-window rate limiting (per-user, in-memory) — exact implementation
Goal: limit abusive pick/unpick attempts; use an in-memory sliding-window per-user rate limiter run before any DB work or validation.
Data structure
 - Module-scoped Map<number, number[]> where key = telegram_id and value = array of timestamps in milliseconds.
 - Example (Node/TS):
   const pickRateLimitMap = new Map<number, number[]>(); // telegram_id -> [tsMs,...]
   const PICK_RATE_LIMIT_WINDOW_MS = 60_000; // 60 seconds
    const PICK_RATE_LIMIT_MAX = 5; // max requests allowed in the window (per-user)

Per-request algorithm (run at the very top of POST /api/games/:gameId/pick handler, before DB queries/locks)
A. const now = Date.now();
B. let timestamps = pickRateLimitMap.get(telegram_id) || [];
C. timestamps = timestamps.filter(ts => now - ts < PICK_RATE_LIMIT_WINDOW_MS); (drop entries older than 60s)
D. if (timestamps.length >= PICK_RATE_LIMIT_MAX) {
 - Respond with HTTP 429 and JSON:
   { "error": "RATE_LIMIT_EXCEEDED", "message": "Too many requests. Try again later." }
 - Frontend should show toast.error("Too many requests. Try again later.").
 - Do not proceed with further processing.
E. else {
 - timestamps.push(now);
 - pickRateLimitMap.set(telegram_id, timestamps);
 - Continue processing the request normally.
F. Notes:
 - This is in-memory only (per-process).
 - Use millisecond resolution for precision.
 - Place the rate-limit check before any DB FOR UPDATE locks to avoid holding locks while responding with 429.

Pseudocode (Postgres Function):

CREATE OR REPLACE FUNCTION pick_board(
    p_telegram_id BIGINT,
    p_target_board SMALLINT
) RETURNS JSON AS $$
DECLARE
    v_game_id           BIGINT;
    v_phase             TEXT;
    v_stake             NUMERIC(12,2);
    v_old_board         SMALLINT;
    v_prev_withdrawal   NUMERIC(12,2);
    v_prev_non          NUMERIC(12,2);
    v_target            RECORD;
    v_user              RECORD;
    v_total             NUMERIC(12,2);
    v_withdrawal_used   NUMERIC(12,2);
    v_non_withdrawal_used NUMERIC(12,2);
BEGIN
    -- 1. Get the current active game (latest game_id) efficiently
    SELECT game_id INTO v_game_id
    FROM games
    ORDER BY game_id DESC
    LIMIT 1;

    IF v_game_id IS NULL THEN
        RETURN json_build_object(
            'success', false,
            'error', 'NO_GAME',
            'message', 'No active game',
            'status_code', 500
        );
    END IF;

    -- 2. Lock the game row and check phase (also fetch stake)
    SELECT phase, stake_amount INTO v_phase, v_stake
    FROM games
    WHERE game_id = v_game_id
    FOR UPDATE;

    IF v_phase != 'picking' THEN
        RETURN json_build_object(
            'success', false,
            'error', 'PICKING_CLOSED',
            'message', 'Picking phase ended',
            'status_code', 409
        );
    END IF;

    -- 3. Silent abort for unregistered users (spec requirement)
    IF NOT EXISTS (SELECT 1 FROM users WHERE telegram_id = p_telegram_id) THEN
        RETURN json_build_object(
            'success', false,
            'error', 'USER_NOT_FOUND',
            'silent', true,
            'status_code', 204
        );
    END IF;

    -- 4. Find user's existing pick in this game (if any)
    SELECT board_id INTO v_old_board
    FROM player_picks
    WHERE game_id = v_game_id AND telegram_id = p_telegram_id
    FOR UPDATE;

    -- 5. Lock both boards (old and target) in ascending order (deadlock-proof)
    PERFORM board_id
    FROM player_picks
    WHERE board_id = p_target_board
       OR (v_old_board IS NOT NULL AND board_id = v_old_board)
    ORDER BY board_id
    FOR UPDATE;

    -- 6. Fetch the target board (now locked)
    SELECT * INTO v_target
    FROM player_picks
    WHERE board_id = p_target_board;

    -- 7. Ensure the target board exists
    IF v_target IS NULL THEN
        RETURN json_build_object(
            'success', false,
            'error', 'INVALID_BOARD',
            'message', 'Board number does not exist',
            'status_code', 400
        );
    END IF;

    -- 9. If target is taken by someone else in the current game → BOARD_TAKEN
    IF v_target.telegram_id IS NOT NULL
       AND v_target.game_id = v_game_id
       AND v_target.telegram_id != p_telegram_id THEN
        RETURN json_build_object(
            'success', false,
            'error', 'BOARD_TAKEN',
            'message', 'Board is selected by others',
            'status_code', 409
        );
    END IF;

    -- 10. Lock the user's wallet
    SELECT withdrawal_wallet, non_withdrawal_wallet INTO v_user
    FROM users
    WHERE telegram_id = p_telegram_id
    FOR UPDATE;

    -- =========================================================================
    -- CASE A: Unpick (clicked own slot)
    -- =========================================================================
    IF v_target.telegram_id = p_telegram_id AND v_target.game_id = v_game_id THEN
        UPDATE users
        SET withdrawal_wallet    = withdrawal_wallet    + v_target.withdrawal_used,
            non_withdrawal_wallet = non_withdrawal_wallet + v_target.non_withdrawal_used
        WHERE telegram_id = p_telegram_id;

        UPDATE player_picks
        SET telegram_id = NULL,
            withdrawal_used = 0,
            non_withdrawal_used = 0,
            picked_at = NULL
        WHERE board_id = p_target_board;

        RETURN json_build_object(
            'success', true,
            'action', 'unpick',
            'refunded', v_target.withdrawal_used + v_target.non_withdrawal_used
        );
    END IF;

    -- =========================================================================
    -- CASE B: First‑time pick (no previous pick)
    -- =========================================================================
    IF v_old_board IS NULL THEN
        v_total := v_user.withdrawal_wallet + v_user.non_withdrawal_wallet;
        IF v_total < v_stake THEN
            RETURN json_build_object(
                'success', false,
                'error', 'INSUFFICIENT_FUNDS',
                'message', 'Insufficient balance to pick',
                'status_code', 402
            );
        END IF;

        -- Priority: use non_withdrawal_wallet first
        v_non_withdrawal_used := LEAST(v_user.non_withdrawal_wallet, v_stake);
        v_withdrawal_used     := v_stake - v_non_withdrawal_used;

        UPDATE users
        SET withdrawal_wallet    = withdrawal_wallet    - v_withdrawal_used,
            non_withdrawal_wallet = non_withdrawal_wallet - v_non_withdrawal_used
        WHERE telegram_id = p_telegram_id;

        UPDATE player_picks
        SET telegram_id         = p_telegram_id,
            game_id             = v_game_id,
            withdrawal_used     = v_withdrawal_used,
            non_withdrawal_used = v_non_withdrawal_used,
            picked_at           = NOW()
        WHERE board_id = p_target_board;

        RETURN json_build_object(
            'success', true,
            'action', 'pick',
            'charged', json_build_object(
                'withdrawal_used', v_withdrawal_used,
                'non_withdrawal_used', v_non_withdrawal_used
            )
        );
    END IF;

    -- =========================================================================
    -- CASE C: Move‑pick (user already has a pick)
    -- =========================================================================
    SELECT withdrawal_used, non_withdrawal_used
    INTO v_prev_withdrawal, v_prev_non
    FROM player_picks
    WHERE board_id = v_old_board;

    -- Clear the old board
    UPDATE player_picks
    SET telegram_id = NULL,
        withdrawal_used = 0,
        non_withdrawal_used = 0,
        picked_at = NULL
    WHERE board_id = v_old_board;

    -- Assign the new board with the same used amounts
    UPDATE player_picks
    SET game_id             = v_game_id,
        telegram_id         = p_telegram_id,
        withdrawal_used     = v_prev_withdrawal,
        non_withdrawal_used = v_prev_non,
        picked_at           = NOW()
    WHERE board_id = p_target_board;

    RETURN json_build_object(
        'success', true,
        'action', 'move',
        'from', v_old_board,
        'to', p_target_board
    );
END;
$$ LANGUAGE plpgsql;

Notes:
 - The server must verify the Telegram initData signature and extract the telegram_id. Do not trust telegram_id coming from the client body.
After commit, Supabase Realtime will broadcast UPDATE for the changed slot(s) — clients receive and update UI.

CREATE OR REPLACE FUNCTION transition_picking()
RETURNS JSONB
LANGUAGE plpgsql
VOLATILE
AS $$
DECLARE
    v_game             games%ROWTYPE;
    v_config           game_config%ROWTYPE;
    v_player_count     INT;
    v_shuffled_nums    JSONB;
    v_prize_amount     NUMERIC(12,2);
    v_house_profit     NUMERIC(12,2);
    v_new_picking_ends TIMESTAMPTZ;
BEGIN
    -- 1. Lock the current (latest) game row
    SELECT * INTO STRICT v_game
    FROM games
    ORDER BY game_id DESC
    LIMIT 1
    FOR UPDATE;

    -- 2. Verify the game is in 'picking' phase
    IF v_game.phase != 'picking' THEN
        RAISE EXCEPTION 'Game is not in picking phase (current phase: %)', v_game.phase
            USING HINT = 'transition_picking() should only be called during picking phase.';
    END IF;

    -- 3. Lock all picked boards for this game (prevent concurrent picks)
    --    Order by board_id to avoid deadlocks with pick_board()
    PERFORM 1
    FROM player_picks
    WHERE game_id = v_game.game_id
      AND telegram_id IS NOT NULL
    ORDER BY board_id
    FOR UPDATE;

    -- 4. Count players who have picked a board
    SELECT COUNT(*)
    INTO v_player_count
    FROM player_picks
    WHERE game_id = v_game.game_id
      AND telegram_id IS NOT NULL;

    -- 5. Fetch the single row from game_config
    SELECT * INTO STRICT v_config
    FROM game_config
    WHERE id = 1
    FOR UPDATE;  -- lock to prevent concurrent changes

    -- 6. Decide whether to extend or start
    IF v_player_count < v_config.minimum_player THEN
        -- Extend picking phase
        v_new_picking_ends := NOW() + (v_config.picking_countdown_end_time * INTERVAL '1 second');

        UPDATE games
        SET picking_ends_at = v_new_picking_ends
        WHERE game_id = v_game.game_id;

        RETURN jsonb_build_object(
            'success', true,
            'action', 'extended',
            'player_count', v_player_count,
            'minimum_player', v_config.minimum_player,
            'new_picking_ends_at', v_new_picking_ends
        );
    ELSE
        -- Enough players → start the game
        -- Generate shuffled numbers 1..75 (random order)
        SELECT jsonb_agg(n ORDER BY random())
        INTO v_shuffled_nums
        FROM generate_series(1, 75) n;

        -- Calculate prize and house profit
        v_prize_amount := ROUND(
            (v_player_count * v_game.stake_amount * v_config.prize_percent) / 100.0,
            2
        );
        v_house_profit := ROUND(
            (v_player_count * v_game.stake_amount) - v_prize_amount,
            2
        );

        -- Update the game row to 'started'
        UPDATE games
        SET phase            = 'started',
            shuffled_nums    = v_shuffled_nums,
            prize_amount     = v_prize_amount,
            active_players   = v_player_count,
            house_profit     = v_house_profit,
            started_at       = NOW()
        WHERE game_id = v_game.game_id;

        RETURN jsonb_build_object(
            'success', true,
            'action', 'started',
            'game_id', v_game.game_id,
            'player_count', v_player_count,
            'prize_amount', v_prize_amount,
            'house_profit', v_house_profit,
            'shuffled_nums', v_shuffled_nums
        );
    END IF;
END;
$$;

4 . Server authority & high-level rules
When a server process sees games.phase === 'started' (i.e., game was moved to started by picking-phase), the Started controller does:
 1. Start an in-memory 3-second timer. While this timer runs:

-- ----------------------------------------------------------------------
-- Helper function: check_bingo
-- Returns TRUE if the card has any winning line (row, column, diagonal,
-- or four corners) using the provided called numbers.
-- The centre cell (row 3, column 3) is always considered marked.
-- Defensively handles missing or malformed JSON cells.
-- ----------------------------------------------------------------------
CREATE OR REPLACE FUNCTION check_bingo(card jsonb, called jsonb)
RETURNS boolean
LANGUAGE plpgsql
STABLE
AS $$
DECLARE
    i INT;
    j INT;
    cell_text TEXT;
    cell INT;
    marked BOOLEAN;
    diag1 BOOLEAN := TRUE;
    diag2 BOOLEAN := TRUE;
    corners_ok BOOLEAN;
    called_set INT[];
BEGIN
    -- Convert called numbers into an array; if none, use empty array
    SELECT COALESCE(array_agg(value::int), '{}'::int[]) INTO called_set
    FROM jsonb_array_elements_text(called) AS t(value);

    -- ------------------------------------------------------------------
    -- Check rows and columns
    -- ------------------------------------------------------------------
    FOR i IN 0..4 LOOP
        -- Row i
        marked := TRUE;
        FOR j IN 0..4 LOOP
            IF i = 2 AND j = 2 THEN
                CONTINUE;  -- centre is free
            END IF;
            cell_text := card->i->>j;
            IF cell_text IS NULL THEN
                marked := FALSE;
                EXIT;
            END IF;
            cell := cell_text::int;
            IF NOT (cell = ANY(called_set)) THEN
                marked := FALSE;
                EXIT;
            END IF;
        END LOOP;
        IF marked THEN
            RETURN TRUE;
        END IF;

        -- Column i
        marked := TRUE;
        FOR j IN 0..4 LOOP
            IF j = 2 AND i = 2 THEN
                CONTINUE;  -- centre is free
            END IF;
            cell_text := card->j->>i;
            IF cell_text IS NULL THEN
                marked := FALSE;
                EXIT;
            END IF;
            cell := cell_text::int;
            IF NOT (cell = ANY(called_set)) THEN
                marked := FALSE;
                EXIT;
            END IF;
        END LOOP;
        IF marked THEN
            RETURN TRUE;
        END IF;
    END LOOP;

    -- ------------------------------------------------------------------
    -- Main diagonal (top‑left to bottom‑right)
    -- ------------------------------------------------------------------
    FOR i IN 0..4 LOOP
        IF i = 2 THEN
            CONTINUE;  -- centre is free
        END IF;
        cell_text := card->i->>i;
        IF cell_text IS NULL THEN
            diag1 := FALSE;
            EXIT;
        END IF;
        cell := cell_text::int;
        IF NOT (cell = ANY(called_set)) THEN
            diag1 := FALSE;
            EXIT;
        END IF;
    END LOOP;
    IF diag1 THEN
        RETURN TRUE;
    END IF;

    -- ------------------------------------------------------------------
    -- Anti‑diagonal (top‑right to bottom‑left)
    -- ------------------------------------------------------------------
    FOR i IN 0..4 LOOP
        IF i = 2 THEN
            CONTINUE;  -- centre is free
        END IF;
        cell_text := card->i->>(4 - i);
        IF cell_text IS NULL THEN
            diag2 := FALSE;
            EXIT;
        END IF;
        cell := cell_text::int;
        IF NOT (cell = ANY(called_set)) THEN
            diag2 := FALSE;
            EXIT;
        END IF;
    END LOOP;
    IF diag2 THEN
        RETURN TRUE;
    END IF;

    -- ------------------------------------------------------------------
    -- Four Corners: (0,0), (0,4), (4,0), (4,4)
    -- ------------------------------------------------------------------
    cell_text := card->0->>0;
    corners_ok := cell_text IS NOT NULL AND (cell_text::int = ANY(called_set));

    cell_text := card->0->>4;
    corners_ok := corners_ok AND cell_text IS NOT NULL AND (cell_text::int = ANY(called_set));

    cell_text := card->4->>0;
    corners_ok := corners_ok AND cell_text IS NOT NULL AND (cell_text::int = ANY(called_set));

    cell_text := card->4->>4;
    corners_ok := corners_ok AND cell_text IS NOT NULL AND (cell_text::int = ANY(called_set));

    IF corners_ok THEN
        RETURN TRUE;
    END IF;

    -- No winning pattern found
    RETURN FALSE;
END;
$$;

-- ----------------------------------------------------------------------
-- Main claim function: claim_bingo (auto-detects current game)
-- Called when a user clicks the BINGO! button during the started phase.
-- It automatically uses the latest game and performs all authoritative
-- checks atomically.
-- ----------------------------------------------------------------------
CREATE OR REPLACE FUNCTION claim_bingo(
    p_board_id     SMALLINT,
    p_telegram_id  BIGINT,
    OUT result     JSONB
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_game          RECORD;
    v_game_id       BIGINT;          -- store the locked game's ID
    v_pick          RECORD;
    v_called_numbers JSONB;
    v_is_win        BOOLEAN;
    v_winner_name   TEXT;            -- to hold the winner's first name
BEGIN
    -- 1. Lock and read the current active game (latest game_id)
    SELECT phase, calling_started, shuffled_nums, called_index, game_id
    INTO v_game
    FROM games
    ORDER BY game_id DESC
    LIMIT 1
    FOR UPDATE;

    IF NOT FOUND THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'No active game');
        RETURN;
    END IF;

    v_game_id := v_game.game_id;      -- save the locked game's ID

    -- 2. Verify game is in started phase and calling has started
    IF v_game.phase != 'started' OR v_game.calling_started != TRUE THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'Game not ready for claims');
        RETURN;
    END IF;

    -- 3. Lock and read the player's pick for this game
    SELECT * INTO v_pick
    FROM player_picks
    WHERE game_id = v_game_id          -- use the saved ID
      AND board_id = p_board_id
    FOR UPDATE;

    IF NOT FOUND THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'Pick not found');
        RETURN;
    END IF;

    -- 4. Check ownership and that the board is not already invalid/winner
    IF v_pick.telegram_id != p_telegram_id THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'Not your board');
        RETURN;
    END IF;

    IF v_pick.invalid THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'Board already invalid');
        RETURN;
    END IF;

    IF v_pick.winner THEN
        result = jsonb_build_object('success', false, 'action', 'ignore', 'message', 'Already a winner');
        RETURN;
    END IF;

    -- 5. Build the list of called numbers up to the current called_index
    SELECT COALESCE(jsonb_agg(value ORDER BY idx), '[]'::jsonb)
    INTO v_called_numbers
    FROM jsonb_array_elements(v_game.shuffled_nums) WITH ORDINALITY AS elem(value, idx)
    WHERE idx <= v_game.called_index;

    -- 6. Validate whether the card actually has a bingo
    v_is_win := check_bingo(v_pick.bingo_card, v_called_numbers);

    IF v_is_win THEN
        -- 7a. Winner – fetch the user's first name
        SELECT first_name INTO v_winner_name
        FROM users
        WHERE telegram_id = p_telegram_id;

        -- Update the pick with winner status and name
        UPDATE player_picks
        SET winner = TRUE,
            winner_name = v_winner_name
        WHERE game_id = v_game_id
          AND board_id = p_board_id;

        -- Build result including the winner's name
        result = jsonb_build_object(
            'success', true,
            'action', 'winner',
            'winner', true,
            'winner_name', v_winner_name,
            'message', 'Bingo confirmed'
        );
    ELSE
        -- 7b. Not a winner – mark the board as invalid
        UPDATE player_picks
        SET invalid = TRUE
        WHERE game_id = v_game_id
          AND board_id = p_board_id;

        result = jsonb_build_object(
            'success', true,
            'action', 'invalid',
            'winner', false,
            'message', 'No bingo'
        );
    END IF;

EXCEPTION
    WHEN OTHERS THEN
        result = jsonb_build_object('success', false, 'action', 'error', 'message', SQLERRM);
END;
$$;

CREATE OR REPLACE FUNCTION finalize_game()
RETURNS JSONB
LANGUAGE plpgsql
AS $$
DECLARE
    v_game           games%ROWTYPE;
    v_winner_count   INT;
    v_prize_cents    BIGINT;
    v_base_cents     BIGINT;
    v_rem_cents      INT;
    v_share_cents    BIGINT;
    v_share_num      NUMERIC(12,2);
    v_winner_rec     RECORD;
    v_result         JSONB;
    v_i              INT := 0;
BEGIN
    -- 1. Lock and fetch the current (latest) game row
    SELECT * INTO v_game
    FROM games
    ORDER BY game_id DESC
    LIMIT 1
    FOR UPDATE;

    IF NOT FOUND THEN
        RETURN jsonb_build_object(
            'success', false,
            'error', 'NO_GAME_FOUND'
        );
    END IF;

    -- 2. Only started games can be finalized
    IF v_game.phase != 'started' THEN
        RETURN jsonb_build_object(
            'success', false,
            'error', 'INVALID_PHASE',
            'phase', v_game.phase,
            'game_id', v_game.game_id
        );
    END IF;

    -- 3. Count winners (NO FOR UPDATE – rows will be locked in the loop)
    SELECT COUNT(*) INTO v_winner_count
    FROM player_picks
    WHERE game_id = v_game.game_id AND winner = TRUE;

    -- 4. Process based on winner count
    IF v_winner_count > 0 THEN
        -- Convert prize to cents for exact distribution
        v_prize_cents := (v_game.prize_amount * 100)::BIGINT;
        v_base_cents  := v_prize_cents / v_winner_count;   -- integer division truncates
        v_rem_cents   := v_prize_cents - v_base_cents * v_winner_count;  -- remainder 0..(v_winner_count-1)

        -- Loop through winners in a deterministic order (e.g., by board_id)
        FOR v_winner_rec IN
            SELECT board_id, telegram_id
            FROM player_picks
            WHERE game_id = v_game.game_id AND winner = TRUE
            ORDER BY board_id   -- stable order
            FOR UPDATE          -- lock each winner row
        LOOP
            v_i := v_i + 1;
            -- First v_rem_cents winners get one extra cent
            IF v_i <= v_rem_cents THEN
                v_share_cents := v_base_cents + 1;
            ELSE
                v_share_cents := v_base_cents;
            END IF;

            -- Convert cents to NUMERIC(12,2) for wallet update
            v_share_num := (v_share_cents::NUMERIC / 100)::NUMERIC(12,2);

            -- Credit the winner's withdrawal wallet
            UPDATE users
            SET withdrawal_wallet = withdrawal_wallet + v_share_num
            WHERE telegram_id = v_winner_rec.telegram_id;

            -- Record in winners_history
            INSERT INTO winners_history (game_id, telegram_id, board_id, credited_amount)
            VALUES (v_game.game_id, v_winner_rec.telegram_id, v_winner_rec.board_id, v_share_num);
        END LOOP;

        v_result := jsonb_build_object(
            'success', true,
            'action', 'winners_credited',
            'game_id', v_game.game_id,
            'winner_count', v_winner_count,
            'prize_amount', v_game.prize_amount
        );

    ELSE
        -- No winners → add the entire prize to the game's house_profit
        UPDATE games
        SET house_profit = house_profit + v_game.prize_amount
        WHERE game_id = v_game.game_id;

        v_result := jsonb_build_object(
            'success', true,
            'action', 'house_credited',
            'game_id', v_game.game_id,
            'prize_amount', v_game.prize_amount
        );
    END IF;

    -- 5. Advance game to winner_reveal with a 10‑second countdown
    UPDATE games
    SET phase = 'winner_reveal'
    WHERE game_id = v_game.game_id;

    -- 6. Return summary
    RETURN v_result;
END;
$$;

CREATE OR REPLACE FUNCTION create_next_game()
RETURNS JSON
LANGUAGE plpgsql
VOLATILE
AS $$
DECLARE
    current_game_id   BIGINT;
    current_phase     TEXT;
    global_status     TEXT;
    new_game_id       BIGINT;
    new_phase         TEXT;
    new_picking_ends  TIMESTAMPTZ;
    new_stake_amount  NUMERIC(12,2);
    config_record     RECORD;
BEGIN
    -- 1. Lock the latest game by its max id – this avoids concurrency issues
    SELECT game_id, phase
    INTO STRICT current_game_id, current_phase
    FROM games
    WHERE game_id = (SELECT max(game_id) FROM games)
    FOR UPDATE;

    -- 2. Verify the game is in winner_reveal (only then can we finish it)
    IF current_phase != 'winner_reveal' THEN
        RAISE EXCEPTION 'Current game phase is not winner_reveal (actual: %)', current_phase
        USING HINT = 'Only a game in winner_reveal can be finished to create the next one';
    END IF;

    -- 3. Mark the current game as finished
    UPDATE games
    SET phase = 'finished',
        finished_at = NOW()
    WHERE game_id = current_game_id;

    -- 4. Lock and read the global game status (prevents admin changes mid‑transaction)
    SELECT status
    INTO STRICT global_status
    FROM game_status
    WHERE id = 1
    FOR UPDATE;

    -- 5. Insert the next game based on global_status
    IF global_status = 'stopped' THEN
        -- 5a. Maintenance game – set all NOT NULL columns explicitly
        INSERT INTO games (
            phase,
            calling_started,
            called_index,
            active_players,
            stake_amount,
            minimum_player,
            picking_ends_at,
            shuffled_nums,
            prize_amount,
            house_profit,
            winner_reveal_ends_at,
            started_at
        ) VALUES (
            'maintenance',
            FALSE,
            0,
            0,
            0,
            0,
            NULL,
            NULL,
            NULL,
            NULL,
            NULL,
            NOW()
        )
        RETURNING game_id, phase, picking_ends_at, stake_amount
        INTO new_game_id, new_phase, new_picking_ends, new_stake_amount;

    ELSE
        -- 5b. New picking game – global_status must be 'active'
        -- Read the current game_config (row id=1 is guaranteed to exist)
        SELECT stake_amount,
               picking_countdown_end_time,
               minimum_player
        INTO STRICT config_record
        FROM game_config
        WHERE id = 1;

        INSERT INTO games (
            phase,
            calling_started,
            called_index,
            active_players,
            picking_ends_at,
            minimum_player,
            stake_amount,
            shuffled_nums,
            prize_amount,
            house_profit,
            winner_reveal_ends_at,
            started_at
        ) VALUES (
            'picking',
            FALSE,
            0,
            0,
            NOW() + (config_record.picking_countdown_end_time || ' seconds')::INTERVAL,
            config_record.minimum_player,
            config_record.stake_amount,
            NULL,
            NULL,
            NULL,
            NULL,
            NOW()
        )
        RETURNING game_id, phase, picking_ends_at, stake_amount
        INTO new_game_id, new_phase, new_picking_ends, new_stake_amount;
    END IF;

    -- 6. Return the details of the newly created game as a JSON object
    RETURN json_build_object(
        'game_id', new_game_id,
        'phase', new_phase,
        'picking_ends_at', new_picking_ends,
        'stake_amount', new_stake_amount
    );

EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RAISE EXCEPTION 'Required configuration row missing (games, game_status, or game_config)'
        USING HINT = 'Ensure tables are seeded with initial data';
END;
$$;

CREATE OR REPLACE FUNCTION recover_game_state()
RETURNS JSON
LANGUAGE plpgsql
AS $$
DECLARE
    current_game      RECORD;
    config            RECORD;
    winner            RECORD;
    global_status     TEXT;
    total_prize       NUMERIC(12,2);
    new_game_id       BIGINT;
    new_game_phase    TEXT;                -- phase of the newly created game
    new_picking_ends  TIMESTAMPTZ;         -- picking_ends_at of the new game
    new_stake_amount  NUMERIC(12,2);       -- stake_amount of the new game
    winner_count      INT;
    has_winners       BOOLEAN;
    winner_list       JSONB := '[]'::JSONB;
    cents_total       BIGINT;
    base_cents        BIGINT;
    last_cents        BIGINT;
    share_cents       BIGINT;
    last_winner_id    BIGINT;
    result_json       JSONB;                -- final JSON to return
BEGIN
    -- Advisory lock to serialise all recovery attempts.
    PERFORM pg_advisory_xact_lock(1);

    -- Lock the latest game row to prevent concurrent recovery attempts
    SELECT * INTO current_game
    FROM games
    ORDER BY game_id DESC
    LIMIT 1
    FOR UPDATE;

    -- If no game exists, create the first one (always maintenance)
    IF NOT FOUND THEN
        INSERT INTO games (phase, stake_amount, minimum_player, picking_ends_at,
                           calling_started, shuffled_nums, prize_amount, house_profit, started_at)
        SELECT 'maintenance', stake_amount, minimum_player, NULL, FALSE, NULL, NULL, NULL, NOW()
        FROM game_config WHERE id = 1
        RETURNING game_id, phase INTO new_game_id, new_game_phase;
        -- No picking_ends_at or stake_amount for maintenance games

        RETURN json_build_object(
            'recovered', true,
            'action', 'initial_game_created',
            'new_game_id', new_game_id,
            'new_game_phase', new_game_phase
            -- picking_ends_at and stake_amount intentionally omitted
        );
    END IF;

    -- Lock and read the global game status
    SELECT status INTO STRICT global_status
    FROM game_status
    WHERE id = 1
    FOR UPDATE;

    -- Lock and read game_config
    SELECT * INTO STRICT config
    FROM game_config
    WHERE id = 1
    FOR UPDATE;

    -- ====================================================================
    -- PHASE: maintenance – nothing to recover
    -- ====================================================================
    IF current_game.phase = 'maintenance' THEN
        RETURN json_build_object(
            'recovered', true,
            'action', 'none',
            'game_id', current_game.game_id,
            'phase', current_game.phase
            -- picking_ends_at and stake_amount omitted
        );
    END IF;

    -- ====================================================================
    -- PHASE: picking – refund all players who have picked a board
    -- ====================================================================
    IF current_game.phase = 'picking' THEN
        -- Lock all player_picks rows that will be refunded
        PERFORM 1 FROM player_picks
        WHERE game_id = current_game.game_id
          AND telegram_id IS NOT NULL
        FOR UPDATE;

        -- Refund players
        UPDATE users u
        SET withdrawal_wallet    = u.withdrawal_wallet + p.withdrawal_used,
            non_withdrawal_wallet = u.non_withdrawal_wallet + p.non_withdrawal_used
        FROM player_picks p
        WHERE p.game_id = current_game.game_id
          AND p.telegram_id IS NOT NULL
          AND p.telegram_id = u.telegram_id;

        -- Mark current game as error
        UPDATE games
        SET phase = 'error',
            finished_at = NOW()
        WHERE game_id = current_game.game_id;

        -- Insert next game based on game_status
        IF global_status = 'stopped' THEN
            INSERT INTO games (
                phase, stake_amount, minimum_player, picking_ends_at,
                calling_started, shuffled_nums, prize_amount, house_profit, started_at
            ) VALUES (
                'maintenance', 0, 0, NULL,
                FALSE, NULL, NULL, NULL, NOW()
            ) RETURNING game_id, phase INTO new_game_id, new_game_phase;
            -- No picking_ends_at or stake_amount for maintenance
        ELSE
            INSERT INTO games (
                phase, stake_amount, minimum_player, picking_ends_at,
                calling_started, shuffled_nums, prize_amount, house_profit, started_at
            ) VALUES (
                'picking',
                config.stake_amount,
                config.minimum_player,
                NOW() + (config.picking_countdown_end_time * INTERVAL '1 second'),
                FALSE,
                NULL,
                NULL,
                NULL,
                NOW()
            ) RETURNING game_id, phase, picking_ends_at, stake_amount
            INTO new_game_id, new_game_phase, new_picking_ends, new_stake_amount;
        END IF;

        -- Build base result
        result_json := jsonb_build_object(
            'recovered', true,
            'action', 'refunded_picking',
            'previous_game_id', current_game.game_id,
            'new_game_id', new_game_id,
            'new_game_phase', new_game_phase
        );

        -- Conditionally add picking_ends_at and stake_amount only if new game phase is 'picking'
        IF new_game_phase = 'picking' THEN
            result_json := result_json || jsonb_build_object(
                'picking_ends_at', new_picking_ends,
                'stake_amount', new_stake_amount
            );
        END IF;

        RETURN result_json;
    END IF;

    -- ====================================================================
    -- PHASE: started – check if any winners exist
    -- ====================================================================
    IF current_game.phase = 'started' THEN
        -- Use EXISTS to get a stable boolean
        SELECT EXISTS (
            SELECT 1 FROM player_picks
            WHERE game_id = current_game.game_id AND winner = TRUE
        ) INTO has_winners;

        IF has_winners THEN
            -- There are winners – credit them
            total_prize := COALESCE(current_game.prize_amount, 0);
            SELECT COUNT(*) INTO winner_count
            FROM player_picks
            WHERE game_id = current_game.game_id AND winner = TRUE;

            IF winner_count IS NULL OR winner_count = 0 THEN
                RAISE EXCEPTION 'Inconsistent state: has_winners = true but winner_count = 0 for game %', current_game.game_id;
            END IF;

            cents_total := (total_prize * 100)::BIGINT;
            base_cents := cents_total / winner_count;
            last_cents := cents_total - (base_cents * (winner_count - 1));

            SELECT telegram_id INTO last_winner_id
            FROM player_picks
            WHERE game_id = current_game.game_id AND winner = TRUE
            ORDER BY telegram_id DESC
            LIMIT 1;

            FOR winner IN
                SELECT telegram_id, board_id
                FROM player_picks
                WHERE game_id = current_game.game_id AND winner = TRUE
                ORDER BY telegram_id
                FOR UPDATE
            LOOP
                IF winner.telegram_id = last_winner_id THEN
                    share_cents := last_cents;
                ELSE
                    share_cents := base_cents;
                END IF;

                UPDATE users
                SET withdrawal_wallet = withdrawal_wallet + (share_cents::NUMERIC / 100)
                WHERE telegram_id = winner.telegram_id;

                INSERT INTO winners_history (game_id, telegram_id, board_id, credited_amount)
                VALUES (
                    current_game.game_id,
                    winner.telegram_id,
                    winner.board_id,
                    share_cents::NUMERIC / 100
                );

                winner_list := winner_list || jsonb_build_object(
                    'telegram_id', winner.telegram_id,
                    'board_id', winner.board_id,
                    'amount', share_cents::NUMERIC / 100
                );
            END LOOP;

            UPDATE games
            SET phase = 'error',
                finished_at = NOW()
            WHERE game_id = current_game.game_id;
        ELSE
            -- No winners – refund all players
            PERFORM 1 FROM player_picks
            WHERE game_id = current_game.game_id
              AND telegram_id IS NOT NULL
            FOR UPDATE;

            UPDATE users u
            SET withdrawal_wallet    = u.withdrawal_wallet + p.withdrawal_used,
                non_withdrawal_wallet = u.non_withdrawal_wallet + p.non_withdrawal_used
            FROM player_picks p
            WHERE p.game_id = current_game.game_id
              AND p.telegram_id IS NOT NULL
              AND p.telegram_id = u.telegram_id;

            UPDATE games
            SET phase = 'error',
                finished_at = NOW()
            WHERE game_id = current_game.game_id;
        END IF;

        -- Insert next game based on game_status
        IF global_status = 'stopped' THEN
            INSERT INTO games (
                phase, stake_amount, minimum_player, picking_ends_at,
                calling_started, shuffled_nums, prize_amount, house_profit, started_at
            ) VALUES (
                'maintenance', 0, 0, NULL,
                FALSE, NULL, NULL, NULL, NOW()
            ) RETURNING game_id, phase INTO new_game_id, new_game_phase;
            -- No picking_ends_at or stake_amount for maintenance
        ELSE
            INSERT INTO games (
                phase, stake_amount, minimum_player, picking_ends_at,
                calling_started, shuffled_nums, prize_amount, house_profit, started_at
            ) VALUES (
                'picking',
                config.stake_amount,
                config.minimum_player,
                NOW() + (config.picking_countdown_end_time * INTERVAL '1 second'),
                FALSE,
                NULL,
                NULL,
                NULL,
                NOW()
            ) RETURNING game_id, phase, picking_ends_at, stake_amount
            INTO new_game_id, new_game_phase, new_picking_ends, new_stake_amount;
        END IF;

        -- Build base result
        result_json := jsonb_build_object(
            'recovered', true,
            'action', CASE WHEN has_winners THEN 'credited_winners' ELSE 'refunded_started' END,
            'previous_game_id', current_game.game_id,
            'new_game_id', new_game_id,
            'new_game_phase', new_game_phase,
            'winners', winner_list
        );

        -- Conditionally add picking_ends_at and stake_amount only if new game phase is 'picking'
        IF new_game_phase = 'picking' THEN
            result_json := result_json || jsonb_build_object(
                'picking_ends_at', new_picking_ends,
                'stake_amount', new_stake_amount
            );
        END IF;

        RETURN result_json;
    END IF;

    -- ====================================================================
    -- PHASE: winner_reveal or finished – just start a new game
    -- ====================================================================
    IF current_game.phase IN ('winner_reveal', 'finished') THEN
        UPDATE games
        SET phase = 'finished',
            finished_at = COALESCE(finished_at, NOW())
        WHERE game_id = current_game.game_id;

        IF global_status = 'stopped' THEN
            INSERT INTO games (
                phase, stake_amount, minimum_player, picking_ends_at,
                calling_started, shuffled_nums, prize_amount, house_profit, started_at
            ) VALUES (
                'maintenance', 0, 0, NULL,
                FALSE, NULL, NULL, NULL, NOW()
            ) RETURNING game_id, phase INTO new_game_id, new_game_phase;
            -- No picking_ends_at or stake_amount for maintenance
        ELSE
            INSERT INTO games (
                phase, stake_amount, minimum_player, picking_ends_at,
                calling_started, shuffled_nums, prize_amount, house_profit, started_at
            ) VALUES (
                'picking',
                config.stake_amount,
                config.minimum_player,
                NOW() + (config.picking_countdown_end_time * INTERVAL '1 second'),
                FALSE,
                NULL,
                NULL,
                NULL,
                NOW()
            ) RETURNING game_id, phase, picking_ends_at, stake_amount
            INTO new_game_id, new_game_phase, new_picking_ends, new_stake_amount;
        END IF;

        -- Build base result
        result_json := jsonb_build_object(
            'recovered', true,
            'action', 'advanced_to_next_game',
            'previous_game_id', current_game.game_id,
            'new_game_id', new_game_id,
            'new_game_phase', new_game_phase
        );

        -- Conditionally add picking_ends_at and stake_amount only if new game phase is 'picking'
        IF new_game_phase = 'picking' THEN
            result_json := result_json || jsonb_build_object(
                'picking_ends_at', new_picking_ends,
                'stake_amount', new_stake_amount
            );
        END IF;

        RETURN result_json;
    END IF;

    -- If we reach here, phase is unknown – do nothing but report
    RETURN json_build_object(
        'recovered', true,
        'action', 'unknown_phase_ignored',
        'game_id', current_game.game_id,
        'phase', current_game.phase
        -- picking_ends_at and stake_amount omitted
    );
END;
$$;

Deposit Acceptor
Build a secure, single-instance deposit_acceptor service (Node/TS + Express recommended) that: receives SMS-forwarder POSTs, parses amount and txn_reference using admin-managed regex rules stored in Postgres (regex_config table), and writes idempotent deposits using a single atomic insert CTE to avoid races. The admin dashboard writes/edits regex_config. The service loads and caches compiled regexes in memory and can reload on demand via a rate-limited wakeup endpoint.

REQUIRED DELIVERABLES
 1. Service with:
  - POST /internal/regex-wakeup — public reload trigger (rate-limited 2/min per IP).
  - POST /sms/gateway/:token — protected SMS ingestion endpoint.
  - In-memory Map<senderName, CompiledConfig[]> swapped atomically.
  - Atomic idempotent insert (CTE).
2. SQL migrations for regex_config and deposits.
3. Unit + integration tests (parsing, reload, duplicate concurrency, rate limits).
4. README: env, admin workflow, reload usage.

deposits (

regex_json (per row — required keys)
JSON
{
  "sender-name":"127",
  "amount-pattern":"You have received ETB\\s+([0-9,]+\\.?[0-9]{0,2})",
  "transaction-id-pattern":"transaction number is[:\\s]*([A-Za-z0-9\\-]{6,40})"
}

 - sender-name: exact match to forwarder sender_name.
 - amount-pattern: capture group 1 = amount.
 - transaction-id-pattern: capture group 1 = txn id.
 - Compile with flags 'iu' by default. Keep patterns specific to avoid catastrophic backtracking.

STARTUP & RELOAD
- On boot or reload:
 1. SELECT regex_config WHERE is_active = true.
 2. Validate required fields exist.
 3. Compile txnRe and amountRe with new RegExp(pattern, 'iu') inside try/catch.
 4. If any compile fails → reject reload (return 500; admin fixes config).
 5. Build Map<senderName, Array<CompiledConfig>> (CompiledConfig = { bankName, senderName, txnRe, amountRe, meta }).
 6. Atomically swap global map reference.

WAKEUP: POST /internal/regex-wakeup
 - POST only; Content-Type: application/json.
 - Rate limit: 2/min per IP; enforce MIN_RELOAD_INTERVAL_MS.
 - Action: re-fetch active rows, compile all; on full success swap map → 200 {ok:true,reloaded:N}; on compile error → 500 {error}.
 - Log caller IP, reloaded count, errors.

SMS INGEST: POST /sms/gateway/:token
 - Path: :token must equal DEPOSIT_GATEWAY_PATH_TOKEN else 404.
 - Header: DEPOSIT_GATEWAY_HEADER_NAME value must equal DEPOSIT_GATEWAY_PASS_KEY else 401.
 - Rate limit: sliding 100/min per IP; return 429 when exceeded.
 - Body JSON: { "sender_name":"127", "sms":"<raw sms text>" }
PROCESS
 1. Missing fields → 422 { parsed:false, reason:'MISSING_FIELDS' }.
 2. configs = map.get(sender_name); if none → 200 { parsed:false, reason:'NO_CONFIG_FOR_SENDER' }.
 3. For each CompiledConfig (order = optional priority):
   - txnMatch = sms.match(txnRe), amtMatch = sms.match(amountRe).
   - If both:
     - txn = (txnMatch[1]||txnMatch[0]).trim().toUpperCase()
     - amount = parseFloat((amtMatch[1]||amtMatch[0]).replace(/,/g,''))
     - If invalid → continue.
     - Perform atomic insert (CTE below).
     - Return:
   	- 201 { inserted:true, deposit_id, bank, txn, amount } or
	- 200 { inserted:false, reason:'DUPLICATE', deposit_id }.
 4. If no match → 200 { parsed:false, reason:'NO_REGEX_MATCH' }.

ATOMIC INSERT (CTE)
WITH ins AS (
  INSERT INTO deposits (bank, amount, txn_reference)
  VALUES ($1,$2,$3)
  ON CONFLICT (txn_reference) DO NOTHING
  RETURNING deposit_id
)
SELECT deposit_id, true AS inserted FROM ins
UNION ALL
SELECT deposit_id, false AS inserted FROM deposits WHERE txn_reference = $3
LIMIT 1;

Params: $1=bankName, $2=amount, $3=txn_reference. Returns {deposit_id, inserted}.
 - LOGGING, METRICS & TESTS
 - Normalize txn (trim+upper) and amount (remove commas).
 - Structured logs: reloads, matches (bank_name, sender_name), inserts, duplicates, auth failures, rate limits.
 - Metrics: deposit_requests_total, deposit_inserts_total, deposit_duplicates_total, regex_reload_total, rate_limit_exceeded_total.
 - Tests: unit regex parsing, integration reload+forward+insert, duplicate concurrency, rate limits, invalid-regex reload rejection.


dmbingo-support-bot — Telegram support notification + lookup bot (On dmbingo-support-bot server)

OVERVIEW
Purpose: Read-only Telegram support bot that notifies a support group about withdrawal requests and provides support-agent lookups. The bot DOES NOT approve or execute withdrawals.
Webhooks are lightweight wake signals only. Neither webhook includes a withdrawal_id.
The bot controls ordering and rate-limiting via Postgres-based locking and an internal worker loop.

REQUIREMENTS
Webhook endpoints (HTTP authenticated)
POST /webhook/withdraw-created
  Content-Type: application/json
  pass-key: 12345678 (make this .env file)
  Body: { "event": "new" }
Behavior: triggers draining of pending withdrawals.
POST /webhook/withdraw-updated
Body: { "event": "updated" }
Behavior: triggers scanning for already-sent withdrawals with status approved/declined to edit or resend messages.
Authentication: either Authorization:  X-SERVICE-SIGNATURE (HMAC-SHA256 of raw body using WEBHOOK_SECRET).

Core behavior
Created wake: drain oldest pending withdrawals in strict FIFO order (ORDER BY withdrawal_id ASC) in batches of 5. Send messages one-by-one with a 3s gap.
Updated wake: scan for rows WHERE status IN ('approved','declined') AND text_status = 'sent' ORDER BY withdrawal_id LIMIT 5 and edit or delete+resend as needed.
Support lookup: accept only plain numeric messages matching ^\d{5,15}$, only from allow-listed support_team_lookup entries with is_active = true.
DATABASE (Postgres) — provide migration SQL files

DESIGN PRINCIPLES
No external queue service. Use Postgres advisory locks and FOR UPDATE SKIP LOCKED to coordinate multiple instances and preserve FIFO order.
Use a single worker loop that claims batches of rows and processes them in-order.
Respect Telegram rate limits by spacing API calls at least SEND_GAP_MS (default 3000ms).
Recovery mechanism: revert processing rows older than configured stale threshold back to pending.
DRAIN LOOP — exact behavior (must be implemented)
Attempt to acquire a Postgres advisory lock (pg_try_advisory_lock) using ADVISORY_LOCK_KEY. If not acquired, another instance is draining; return.
Claim up to BATCH_SIZE (default 5) pending rows atomically and set text_status='processing' and processed_at=now():

BEGIN;
WITH c AS (
SELECT withdrawal_id
FROM withdrawals_request
WHERE text_status = 'pending'
ORDER BY withdrawal_id
LIMIT $1
FOR UPDATE SKIP LOCKED
)
UPDATE withdrawals_request
SET text_status = 'processing', processed_at = now()
FROM c
WHERE withdrawals_request.withdrawal_id = c.withdrawal_id
RETURNING withdrawals_request.*;
COMMIT;

For each claimed row, in the returned order:
Format a complete Telegram message using HTML parse mode (escape <, >, &).
Call sendMessage(SUPPORT_CHAT_ID, text, { parse_mode: 'HTML' }).
If send succeeds: UPDATE withdrawals_request SET tg_message_id=$1, text_status='sent', attempts=0 WHERE withdrawal_id=$2.
If send transiently fails: increment attempts; if attempts >= MAX_ATTEMPTS mark as failed and log for manual review.
Wait SEND_GAP_MS between each Telegram API call.
Release advisory lock (pg_advisory_unlock).
Repeat claiming and processing while pending rows exist, bounded by MAX_BATCH_ITERATIONS_PER_WAKE to prevent runaway in a single webhook call.
UPDATE LOOP (no withdrawal_id provided)
Acquire advisory lock.
Claim up to 5 rows WHERE status IN ('approved','declined') AND text_status = 'sent' ORDER BY withdrawal_id LIMIT 5 FOR UPDATE SKIP LOCKED.

For each row:
If created_at >= now() - interval '47 hours' AND tg_message_id exists => editMessageText to replace entire message.
Else => attempt deleteMessage (ignore errors), then sendMessage new message and update tg_message_id.
After success: set text_status='finished', set processed_at.
Sleep SEND_GAP_MS between Telegram API calls.
Release advisory lock.

MESSAGE FORMAT (HTML)
Use parse_mode 'HTML' and escape special characters. Exact format:

💳 Withdrawal request {withdrawal_id}
Telegram ID: {telegram_id}
Status: {🟠(pending) | ✅(approved) | ❌(declined)}

🏦 Bank Details
Bank: {bank}
Account Holder Name: {account_holder_name}
Account Number: {account_num}
Amount: {amount} ETB

ℹ️ Transaction Info
Tx Number: {admin_tx_number || '-'}
Admin Name: {admin_first_name || '-'}
Decline Reason: {declined_reason || '-'}
Requested At: {created_at YYYY-MM-DD HH:mm}
Processed At: {processed_at || '-'}

If message is delete+resent due to age, append ' (reposted)'. Include an inline button: 'View in Admin' linking to admin URL.

SUPPORT LOOKUP
Accept only text matching ^\d{5,15}$.
Verify sender's telegram_id exists in support_team_lookup with is_active=true. If not, ignore.
Query users by telegram_id. If not found -> reply '👤 User doesn't exist'.
If found, fetch and format:

first_name
phone_number masked like: show first 7 chars + 'xxxx' + last 2 chars (e.g., +251910xxxx02)
withdrawal_wallet, non_withdrawal_wallet (two decimals)
referral_count, last_referred
last 10 deposits: created_at | amount | status
last 10 withdrawals: created_at | amount | status | declined_reason
last 10 transfers: created_at | +/-amount | counterpart masked phone
last 10 wins: won_at | credited_amount

ERROR HANDLING, RETRIES & RATE LIMITS
On Telegram 429, parse Retry-After and sleep accordingly. Use exponential backoff for retries.
If sendMessage succeeded but DB update fails, retry DB update several times; if DB unreachable, log error and set row back to pending if necessary.
Use MAX_ATTEMPTS (default 5) and surface permanently failing rows to an admin monitoring route.

RECOVERY JOBS
Periodic job (every minute) to revert processing rows older than PROCESSING_STALE_MINUTES back to pending:

UPDATE withdrawals_request
SET text_status='pending'
WHERE text_status='processing'
AND processed_at < now() - interval '10 minutes';

Create Coupon page ( super admin only)
Top area
Title: Coupons
Button (top-right): Create New Coupon (primary orange). Visible only to super_admin.
Create New Coupon modal (opens when clicking button)
Modal Header: Create New Coupon
Modal Body (form fields, each required unless noted):
Coupon Code — single-line text input
Client validation: alphanumeric + -_ allowed, max 20 chars; show helper Example: WELCOME50.
Backend enforces UNIQUE.
Coupon Prize — number input (decimal allowed)
Validation: > 0, up to 2 decimals.
Max Uses Total — integer input
Validation: integer ≥ 1.
Admin Action Password — password textarea/input (required)
Purpose: re-authenticate the admin. Submitted to backend for validation.
Starts At — date-time picker (TIMESTAMPTZ, TZ-aware)
Default: now.
Expires At — date-time picker (TIMESTAMPTZ, TZ-aware)
Validation: expires_at > starts_at.
Credit To — select: Withdrawal Wallet / Non-Withdrawal Wallet (maps to DB credit_wallet values).
Modal Footer:
Close (closes modal) — secondary button
Create (primary) — disabled until all validation passes and password field is non-empty
Create flow:
On click Create: send POST admin coupons with body:
{
  "coupon_code": "WELCOME50",
  "coupon_prize": 5.00,
  "max_uses_total": 100,
  "starts_at": "2025-10-06T12:00:00Z",
  "expires_at": "2025-10-31T23:59:59Z",
  "credit_wallet": "non_withdrawal",
  "admin_password": "<entered>"
}

Backend:
Verify admin action password (re-auth). If wrong → 401 + toast.error("Password incorrect".)
Validate fields, ensure unique coupon_code.
Insert into coupons with status = 'active', current_uses = 0, created_by_admin = admin_id.
Log to admin_actions with action = 'create_coupon' and details containing coupon meta (exclude admin action password).
Return created coupon row.

Frontend:
On success: close modal, toast.success("Coupon created and set to ACTIVE"), refresh coupons table.
Coupons Table (under Create button) Columns: Coupon ID, Coupon Code, Prize, Credit To (Withdrawal / Non-Withdrawal), Max Uses, Current Uses, Starts At, Expires At, Status (colored pill: active=green, expired=gray, finished=red), Created By (admin username), Actions (right-most)

Behavior:
Server-side pagination (200 rows/page by default) and server-side search by coupon_code, date range filter (starts_at/expires_at), and sort by created_at or expires_at.
Action button per row: Finish (visible only when status = active or expired). Color: danger/outline.
Clicking Finish opens a small re-auth modal: "Are you sure?" with Close and Sure! buttons. Also asks for admin action password. On Sure! with valid password, backend sets status = 'FINISHED'. Log to admin_actions with action 'finish_coupon'.
On success: table row updates to FINISHED, toast.success.
Row-level inline tooltip to show remaining uses: Max 100 | Used 12 | Remaining 88.
Export CSV button (filtered results) for audit.

Coupon History Page (super admin only)
Read-only table.
Columns: Claimed ID, Coupon Code (join), Coupon ID, User Telegram ID (link to /admin/users/:telegram_id), Claimed At (TIMESTAMPTZ), Coupon Prize, Credit To (wallet where prize was credited)
Behavior:
Server-side pagination + server search by coupon_code, user_telegram_id, date range.
Export CSV.

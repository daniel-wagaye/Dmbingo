Title: Bank Regex Configurations
Top actions
 - Primary (neon orange): Create Regex — visible only to SuperAdmin. Opens Create Regex modal which requires the Admin Action Password to submit.
 - secondary (cyan) : Weak up button -  when clicked without asking anything it sends POST https://deposit-acceptor.onrender.com/internal/regex-wakeup -H "Content-Type: application/json" -d "{}" make this .env file so i can edit it.

Table columns
ID | Bank Name | Regex JSON | Is Active | Created At | Updated At | Actions

- Row content:
  - Bank Name — plain text.
  - Regex JSON — truncated preview (e.g., {"sender-name":"127",...} — max 60 chars). Clickable to expand inline (accordion-style, full pretty-printed JSON).
    When expanded:
     - Full JSON displayed (read-only, syntax-highlighted via JSON.stringify(..., null, 2)).
     - Test button (neon cyan) below it.
  - Is Active — green check (✅) / red X (❌) pill.

- Actions (right-most): Edit (pencil icon) | Delete (trash, dangerous).

Create Regex modal
- Header: Create Bank Regex Configuration
- Fields:
  - Bank name — required, max 64 chars, unique (server-enforced).
  - Regex JSON — textarea (300 chars max).
Inline helper text: Paste full JSON object (exact format):
  JSON{
  "sender-name": "127",
  "amount-pattern": "You have received ETB\\s+([0-9,]+\\.?[0-9]{0,2})",
  "transaction-id-pattern": "transaction number is[:\\s]*([A-Za-z0-9\\-]{6,40})"
}
 - Must be valid JSON
 - Must contain keys: "sender-name", "amount-pattern", "transaction-id-pattern"
 - All three values must be non-empty strings
 - Show red error if invalid.
- Is Active — checkbox, default checked.
- Admin Action Password — required (SuperAdmin only). Must be sent to server for verification.

Buttons: Close, Create (primary) — disabled until JSON is valid.
On Create:
POST /admin/regex with body:
JSON
{
  "bank_name": "...",
  "regex_json": "{...full json string...}",
  "is_active": true,
  "action_password": "..."
}

Server must:
1. Verify role = super_admin + action_password
2. JSON.parse() the regex_json string
3. Validate required keys exist
4. Compile both regex patterns with new RegExp(pattern, 'iu') → if any fails → return 400 with error
5. Insert into regex_config (regex_json stored as JSONB)
6. Log admin_actions → create_regex
On success → close modal, toast.success, refresh table, trigger POST https://deposit-acceptor.onrender.com/internal/regex-wakeup -H "Content-Type: application/json" -d "{}" make this .env file so i can edit it.

Edit Regex modal
Header: Edit Bank Regex — #{id}
 - Prefill: bank_name + full regex_json string + is_active checkbox
 - Same fields & client-side validation as Create
 - Buttons: Close, Save (primary)

On Save:
PUT /admin/regex/:id with same body as Create
Server performs same validation + audit log edit_regex (before/after)

Delete flow (destructive)
- Click Delete → confirmation modal (danger).
  - Message: Are you sure you want to permanently delete regex for {bank_name}? This may affect deposit parsing.
  - Require Admin Action Password input.
  - Buttons: Cancel, Delete (danger).
  - On Delete submit: DELETE /admin/regex/:id with { action_password }. Server must verify role + action_password, delete, and write admin_actions { action: 'delete_regex', actor_id, target_id, details }. On success: toast success, refresh list.

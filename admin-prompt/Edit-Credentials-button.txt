Edit Credentials button (For all(super admin + withdrawal admin))
When clicked, the app opens a modal appropriate to the authenticated admin's role:
 - If the user is a Super Admin → open the Super Admin modal.
 - If the user is a Withdrawal Admin → open the Withdrawal Admin modal.
Do not show or render the other role's modal or any other edit controls.

USER INTERFACE (UX) — global
- Button
  - Label: Edit Credentials
  - Visible only after successful auth and role determination.
  - Clicking triggers role check and opens the modal for that role.
- Modal general attributes
  - role = "dialog", aria-modal = "true"
  - Heading text differs by role:
    - Super Admin heading: Manage Account Credentials (Super Admin)
    - Withdrawal Admin heading: Change Your Password (Withdrawal Admin)
  - Modal behavior
    - Focus is trapped inside while open.
    - First focusable element is the radio group.
    - Esc closes the modal.
    - Enter triggers the primary button when focus is in a field.
    - Modal is fully keyboard accessible; radio group supports arrow keys to change selection.
  - Accessibility: Every input must have a visible label, an aria-describedby referencing helper or validation text when present, and error messages must use role="alert" and reference the input with aria-describedby.

SUPER ADMIN MODAL — layout & fields
- Radio group (first element) with three options:
  - Login Password (value "login")
  - Action Password (value "action")
  - Email Address (value "email")
  - Keyboard accessible, aria-label "Choose credential to edit"
- For Login Password or Action Password selection:
  - Field: Your registered email (required)
    - Label: "Your registered email"
  - Field: New password (required)
    - Label: "New password"
  - Field: Confirm new password (required)
    - Label: "Confirm new password"
  - Button: Send Verification Code
    - Text: "Send Verification Code"
    - Disabled until the three fields (email, new password, confirm) are valid.
  - Verification area (hidden until "Send Verification Code" is completed successfully):
    - Message: "A verification code was sent to Your Email Address. Please enter the code."
    - OTP input: single field, numeric inputmode, maxlength 6
      - Label: "Verification code"
      - Placeholder: "Enter 6-digit code"
    - Timer: visible countdown showing "Expires in mm:ss"
    - Button: Update Password (submit)
      - Text: "Update Password"
      - Disabled until OTP present and password fields valid
- For Email Address selection:
  - Field: Current email (required)
    - Label: "Please enter your current email address"
    - Inline hint: "Must match the email currently on your account."
  - Field: New email (required)
    - Label: "Please enter your new email address"
  - Button: Verify and Send Codes
    - Text: "Verify and Send Codes"
    - Disabled until both email fields valid
  - Verification area (hidden until send succeeds):
    - Message: "A verification code was sent to your Current Email Address, and another to your New Email Address. Please enter the codes below."
    - Input 1: Code for current email
      - Label: "Code sent to current email"
    - Input 2: Code for new email
      - Label: "Code sent to new email"
    - Timer: "Expires in mm:ss"
    - Button: Update Email
      - Text: "Update Email"
      - Disabled until both codes present and valid format

WITHDRAWAL ADMIN MODAL — layout & fields
- Radio group (first element): Login Password | Action Password
- Field: Current Action Password (required)
  - Label: "Current Action Password"
  - This is mandatory for any change (login or action).
- Field: New password (required)
  - Label: "New password"
- Field: Confirm new password (required)
  - Label: "Confirm new password"
- Button: Change Password
  - Text: "Change Password"
  - Disabled until all fields valid
PASSWORD POLICY (client + server)
- Requirements:
  - Minimum length: 8 characters
  - At least one uppercase letter
  - At least one lowercase letter
  - At least one digit
  - At least one symbol (non-alphanumeric)
- Confirm new password must exactly match new password.
- Client must show inline, specific error messages when the password does not meet each rule. Example messages:
  - "Password must be at least 8 characters."
  - "Password must contain at least one uppercase letter."
  - "Passwords do not match."
- Server must re-validate the same policy regardless of client validation.
- OTP LIFECYCLE & RULES is the same as the login page forgot password.

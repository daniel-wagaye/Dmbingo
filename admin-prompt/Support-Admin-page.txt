Support Admin page (SuperAdmin only)
Title: Support Admins
Top actions
 - Primary (neon orange): Create Support Admin — visible only to SuperAdmin. Opens Create Support Admin modal requiring Admin Action Password.

Table columns
ID | Telegram ID| Name | Active | Created At | Updated At | Actions
 - Row content: {telegram_id} — {is_active ? 'active' : 'inactive'}.
 - Actions (right-most): Edit (pencil) | Reactivate / Deactivate (toggle) | Delete (trash)

Create Support Admin modal
 - Header: Create Support Admin
 - Fields:
    - telegram_id — required numeric (BIGINT).
    - name - TEXT (3-10 characters).
    - is_active — boolean (default true).
    - Admin Action Password — required (SuperAdmin only).
 - Buttons: Close, Create

API & server behavior (on Create)
 - POST /admin/support_admins with { telegram_id, is_active, action_password }
Server must:
 1. Authenticate & confirm role = SuperAdmin.
 2. Verify action_password.
 3. Validate telegram_id uniqueness (enforce unique constraint).
 4. validate name is only 3-15 charachters)
 5. Insert into support_admin table and return 201. 
 6. Append admin_actions audit: { action: 'create_support_admin', actor_id, target_id, details: { telegram_id + name } }.

Edit Support Admin modal
 - Header: Edit Support Admin — #{id}
 - Prefill fields. Allow editing all fields
 - Admin Action Password required.
 - On Save: PUT /admin/support_admins/:id — server verifies password, updates, writes admin_actions { action:'edit_support_admin', before, after }, and returns 200.

Reactivate / Deactivate flow
 - Quick toggle in row or dedicated modal that requires Admin Action Password for reactivation.
 - On Reactivate: POST /admin/support_admins/:id/reactivate with { action_password, force_reload: boolean }. Server verifies and writes admin_actions.

Delete flow
 - Confirm modal (danger) requiring Admin Action Password. On success: DELETE /admin/support_admins/:id, server writes admin_actions and returns 200.
